# Native output Poll / result initialization — independent static audit

2026-11-07, in-progress source snapshot. Read-only audit; no build, execution, Git or GPU validation by this reviewer. Root owns running validation. Test regression preparation is separately authorized and is not a passing receipt.

## Actual finding: generation physical count loses prior slot incarnations

`gdextension_production_output_poll.cpp:127–146` adds `slot.physical_returned` only when storage is absent; while storage exists it counts only current storage witnesses. The counter is cumulative: `particles_storage_retire.cpp:451` increments it once per valid physically RETURNED resource, before advancing `retire_resource`, while storage stays alive until the later destruction turn at lines455–467. `external_output_owner.cpp:485` resets `retire_resource` on slot pin return but retains `physical_returned`. `select_slot` accepts RELEASED slots (lines216–233), and acquire at `gdextension_production_output.cpp:568–610` installs a new storage without resetting that counter.

Therefore after the first incarnation's N returns, a new live incarnation reports 0 instead of N, then reports only its current witnesses until destruction restores the cumulative 2N. This violates the generated ABI's documented whole-generation physical count. It is a source-level confirmed defect, independently reported to root. Public non-SceneOnly profile admission remains gated, so this is not a claim of externally executed raster reproduction.

Correct arithmetic must always include cumulative `slot.physical_returned` and count current RETURNED witnesses only for resource indices >= `slot.retire_resource`. Earlier valid resources have already been included by the original receipt cursor. Simply adding the cumulative count to all current witnesses double-counts the consumed prefix while storage is still alive. Still observe all witnesses for errors/UNKNOWN even where their returned count is already in the cumulative prefix.

Directed regression: a real public SceneOnly Create and original generation pin; explicit CPU-only private slot projection with two storage incarnations and receipt cursor advancement. All physical facts must come from real original RD storage factories, `_native_disposal_free`, `_free_pending_resources`, and original witness observations. Expected sequence per two-resource incarnation: previous total with new LIVE storage; previous+2 after both actual returns; same total after cursor consumes first, then second resource; same total after storage removal. Second incarnation must start at2 and finish at4. A naive cumulative+all-current fix fails the partial cursor checks. This models private bookkeeping, not public Acquire/Instance192/GPU readiness.

## Verified structure

- Poll authenticates exact installed physical RECORD context/request using append=false; requires original main RD and owner particle RID/device/generation/registry. It takes Registry then RD try-lock. It does not schedule controls, retain new pins, issue driver operations, invoke native completion polling, advance action/revision, consume controls or run disposal. `_native_disposal_observe` reads a retained witness cell only. `production_report_locked` projects existing request facts only.
- known/possible/complete come from that exact request's production report, rather than from another request in the same attachment. Physical aggregation scans every slot of the validated generation, independently of which slot associated the polling request. UNKNOWN from storage or read cells affects custody/status.
- Released generation remains observable while the particles metadata owner exists: retained generation registry/request/root scalars are checked; empty generation pin is allowed only for RELEASED. Original generation cleanup preserves those cold scalars. Slot cleanup preserves request/action/lease incarnation, permitting that request's association after return. Actual `particles_free` removes the owner and Poll then rejects it.
- Poll starts with zeroed result, correct ABI, action_ordinal UINT64_MAX and invalid-parameter status. It publishes request/action association only after original generation/request/slot validation. No unique slot action (including generation-only request), or multiple actions, yields UINT64_MAX.
- Acquire starts with zeroed result, action_ordinal UINT64_MAX and every inactive resource/use locator UINT32_MAX. Writable count remains zero on validation failures. Projection writes active locators only after exact action/owner association. Invalid ordinal is range checked before indexing.
- Prepare is a status-only DTO operation, with no writable result. It rejects invalid/out-of-action anchor/source/role locators; absent roles require both locator sentinels and zero generation/bytes. No action prepared mutation occurs until all validations finish.
- Cancel closes slot publication/pass and sets RETIRING. Exact duplicate Acquire sees RETIRING and returns retained-prefix custody, ERR_BUSY, no descriptors; it cannot pass BOUND writable projection. After actual unpin, action becomes RETURNED and duplicate remains without descriptors. Live BOUND duplicate additionally rechecks owner/slot/pin, full source span, alias witnesses, effects and source loss under original Registry/RD locking.
- Public Acquire/Poll leaves validate complete aligned/disjoint input and output extents before entering Registry. Invalid pointer/overlap returns without writing an unvalidated output; result initialization guarantees concern valid writable output DTOs.

## Root correction re-review

After root-reported directed RED (1 case, 216 assertions, four physical-return mismatches), independently reread the revised production aggregation loop. It now adds every slot's cumulative physical_returned before checking storage; observes every nonnull witness, including the already consumed prefix, preserving error/UNKNOWN behavior; and adds current RETURNED only when resource index >= retire_resource. This matches the actual original retirement ordering and avoids both reuse loss and partial-prefix double counting. With storage absent only cumulative receipts remain; after slot return resets cursor0 and new storage is installed, prior cumulative receipts remain plus only the new incarnation's witnesses. No new counting defect identified in this corrected snapshot. Root green build/run remains separate evidence, not performed by this reviewer.
