1. ORIGINAL OWNER / GENERATION / TOKEN
- Registration accepts only direct CallableCustomExtension (dynamic_cast), adopted original holder, valid original owner and actual call_func. Core field inspection avoids invoking DSO is_valid/hash/compare/string functions as admission. Bound/unbound wrappers are correctly excluded from this internal direct-holder domain.
- Private registration helper checks owner Registry identity, QUALIFIED enrollment, attached/open generation and exact CleanupAction storage owner slot/generation, excluding pending or already-disposed holder. It copies only the original Callable reference, so owner RecordRef and cleanup stay rooted in the existing callable lifetime; it does not fabricate a code hold or cleanup permit.
- Relay token includes Registry instance and unique serial. Delivery rechecks attached/quiescing/close/generation/enrollment. Holder observation matches record slot + generation + exact holder serial, so another Callable in the same generation cannot acknowledge this one. Holder close state remains inspectable without pinning a reclaimed library record.
- begin_cycle refuses nonempty/live relay cells before changing instance; only empty/closed observations are reset. Old tokens become invalid in a new instance.

2. THREAD / REENTRANCY / CONCURRENCY
- All cell lookup/state transitions and active-delivery reservation use Registry mutex. normal_relays is a fixed array: a reserved relay pointer remains stable.
- Delivery increments active_deliveries before unlocking and calls the original Callable without copying it onto the delivery thread. release refuses while deliveries active; forget requires no active/releasing/callback and actual holder_closed. Thus neither release nor cell reuse can race an admitted delivery's access to callback.
- Actual DSO entry still goes through CallableCustomExtension::call -> enter -> CallbackScope. If generation closes between relay reservation and actual DSO admission, CallbackScope refuses it; the relay's original Callable holder continues to pin lifetime. The relay reservation itself is not treated as admitted DSO work.
- Cancellation linearizes against subsequent reservations, while already-reserved calls may complete; release_requested cancels first and returns ERR_BUSY for active/reentrant calls. Caller must retry release later (the test does so). This is explicit fallible release, not an automatic deferred release claim.
- release checks the original CleanupAction::Storage thread_id before changing flags, so a foreign-thread release leaves state unchanged. It copies to a local destruction-thread Callable, clears the registry ref while the local still pins it, unlocks, then drops local. Therefore final DSO destruction executes outside Registry mutex and on the original registered destruction thread. Reentrant release/forget during free sees releasing=true and cannot reuse the cell.
- After decrementing active_deliveries, call_normal_relay does not dereference relay again. A concurrent legal forget at that point therefore cannot invalidate any later relay access in that call.

3. TRUE HOLDER RETIREMENT
- cell_released means the Registry's Callable ref has been dropped and no release is in progress; it intentionally does not imply actual holder retirement.
- holder_closed is set only by unlink_holder_locked on exact original holder. Existing destructor enters CleanupScope, runs free_func, and only after its return retires the CleanupAction. Existing retire_binding_holder / finish_retiring_holders also defer unlink to the proper outer admitted frame when required. This preserves actual-return semantics rather than treating cancel, ref drop, or entry into free_func as acknowledgment.
- forget requires holder_closed plus empty callback and zero active/releasing state. Assigning an empty NormalRelay under mutex cannot invoke DSO code. A forgotten relay leaves only the harmless boolean normal_relay_observed on an already retired holder.
