# Ordinary MultiMesh resource regression fixtures

The resource scripts exercise existing public RenderingServer APIs on the actual main RD, outside active lists. `native_neighbors.gd` additionally checks ordinary scene color pixels. These are K02 constituents; they do not replace original E34 M01–M12/N03 acceptance or qualify performance, physical release, allocation/driver-fault injection, full B4, or ExternalOutputStorage.

Use the actual tests-enabled editor binary with this directory as `--path`:

- `--rendering-method mobile --rendering-driver metal --script matrix.gd`: command contents, indirect transitions, same-mesh capacity/layout changes, null/empty and in-place surface changes, and CPU-cache-less automatic AABB refresh. Readback deliberately synchronizes; it does not prove non-stalling production scheduling. No MultiMesh is attached to a drawable scene instance, so the sentinel negative never submits an unsafe indirect draw.
- `--rendering-method mobile --rendering-driver metal --script cached_visible.gd`: a hidden CPU-cache dirty region survives two flushes and must upload when `visible=-1` admits it; explicit capacity is the independent healthy control.
- `--rendering-method gl_compatibility --rendering-driver opengl3 --script gles_visible.gd`: original visible1/all(-1)/zero behavior and invalid-allocation state preservation.
- `--rendering-method forward_plus --rendering-driver metal --script motion.gd`: original native TAA motion requirement, actual current/previous GPU buffer contents, motion enable and same-mesh resize.
- `--rendering-method forward_plus --rendering-driver metal --script native_motion_history.gd`: actual ordinary MultiMesh velocity texture pixels across initial, two +1 movements, same-mesh capacity3→5, a further +1 movement and hold. An empty scene first establishes camera history. A public compositor requests motion vectors; after each completed one-shot viewport draw, a bounded compute pass samples the native R16G16_SFLOAT velocity into an owned float32 SSBO. Main-RD buffer readback occurs outside active render lists; no main-RD submit/sync is used. At orthographic width8, +1 world has literal prev-current velocity(-1/8,0), tolerance2^-12. Six stages check108 velocity samples and6 green-position color samples. `--omit-second-move` must fail exactly9 second-move velocity samples and1 corresponding color sample, preserving every other stage. This is native opaque MultiMesh history consumption, not the External late-velocity path, TAA quality, all materials or wholeM09 acceptance.
- `--rendering-method mobile --rendering-driver metal --script native_neighbors.gd`, also Forward+: fixed 96×96 color samples for an ordinary red Mesh, green MultiMesh and blue native GPUParticles. All-visible, visible0, visible-1 and same-mesh capacity3→5 stages must preserve the other contributors. The masks and literal RGB values are fixed before rendering, with per-channel tolerance1/255; every sample and stage is logged. This observes color only, not depth, shadow or native physical return. Set `GODOT_TEST_K02_NEIGHBOR_OUT` to an existing absolute directory to save the four viewport PNGs; a requested artifact write failure fails the test.
- `--rendering-method mobile --rendering-driver metal --script native_indirect.gd`, also Forward+: a real ordinary RenderingServer MultiMesh RID participates in the same 96×96 red/green/blue scene. Fixed samples check direct→indirect→direct, visible0/-1 and indirect capacity3→5. On the render thread outside render lists the fixture changes only the documented instance-count word of the existing indirect command to0 and then3 while logical visibility remains -1; black then green pixels demonstrate consumption. It records the original `buffer_update` Error and each stage's logical state. This is a color-pixel constituent, not a completion or physical-retirement observation. The optional `GODOT_TEST_K02_NEIGHBOR_OUT` directory saves each stage PNG.
- `native_depth_shadow.gd`: ordinary Mesh/MultiMesh/native GPUParticles depth and directional-shadow pixels across visible0/-1 and capacity3→5. An orthographic camera near1/far9 at z5 gives native reversed depths .5/.625/.375 for z0/+1/-1; a transparent screen quad displays the sampled depth as sRGB grayscale. Fixed 3×3 interior masks compare those encoded values within1/255, not raw float depth. A separate receiver's custom light shader exposes directional shadow attenuation as black/white; casters at z.6 and a -45° Y light produce fixed +.6 X shadow positions. Each run saves six PNGs and checks216 samples. `--omit-multimesh-depth` and `--omit-multimesh-shadow` user arguments are ordinary public-material/caster controls: each must fail exactly18 target samples and keep all neighbors correct. No native driver or engine fault is injected.
- `native_simulation.gd`: a planar native GPUParticles process with speed2, zero forces/randomness, `fixed_fps=4`, `speed_scale=0`, interpolation off and one particle with lifetime8. The ordinary material integrates the initial forced clear step: x=-1.5 becomes-1 (pixel32). Separately consumed public `request_particles_process(.25,0)` calls then give pixels40/48. A no-request hold stays fixed; MultiMesh resize3→5 preserves the static neighbors. Fractional-delta and preprocess.5 profiles exercise their original paths, and zero velocity stays at pixel24. Four stages sample all five possible blue positions plus red Mesh/green MultiMesh/background:288 fixed samples. Omitting only the second request must fail exactly18 target samples. This witnesses simple planar native simulation advancement, not arbitrary particle algorithms or a finished-signal completion guarantee.
- `--rendering-method mobile --rendering-driver metal --script invalid_allocation.gd`, also Compatibility/OpenGL: invalid enum rejects before original interpolation/native owner state mutation. Exactly one native dimensions diagnostic is expected; its result must preserve original capacity. No huge GPU allocation is attempted. The separate doctest checks arithmetic endpoints.

For a `template_release` build, provide its build receipt and add `--pack-editor-receipt /absolute/clean-editor-build.json`. The helper creates a normal main scene and sidecar `godot.pck` with `PCKPacker`, then launches an exact copy of the template executable. The source SceneTree entry becomes a Node `_ready` entry, with explicit tree-root, frame and quit references; the sampling body and rendering APIs are preserved. `PACKAGE.json` records those exact adaptations, source/PCK/binary hashes, the actual packing Editor identity and complete packing command/log. The template runs its normal packaged scene entry. Editor packing and actual non-editor release rendering are separate recorded operations; the Editor's headless packing step is not a GPU result.

The surface encoder intentionally clamps a nonempty mesh AABB to a 1e-5 minimum size per axis (`RenderingServer::_surface_set_data`); the auto-AABB literals include that native z extent. Clear/remove use two nontrivial 2D instance transforms and separated surfaces, so refreshing before final mesh bounds would fail the exact x bounds.

An absent main RD exits77 for RD fixtures, never a GPU PASS. Full original rendering/physical-return/failure tests remain conjunctive and are not claimed here.

Motion-history update profiles additionally cover the original CPU-cache path. Add one of `--cached-transform`, `--cached-start-hidden`, `--cached-hidden-first` or `--cached-late-motion` to the wrapper (and repeat its `--omit-second-move` control). Cached transforms use public per-instance setters with the same geometry. Start-hidden first uploads with visible0, then reveals the unchanged allocation. Hidden-first uses1536 bounded instances/visible1024: only hidden index1024 is dirty in an earlier frame, so the two visible dirty regions have no update; normal initial data follows. Late-motion first renders cached x=-2 without requesting motion, then enables the compositor's motion requirement and sets x=-1: this first observed stage has literal velocity(-1/8,0), preserving actual earlier cached history. Other stages and tolerances retain their original fixed expectations. These are separate normal data-path controls, not allocation/fault injection. The first fresh cached allocation and resize use current transforms as previous until an actual nonempty update initializes GPU data; successful nonempty cached updates mark the buffer initialized. Ordinary existing motion then preserves previous-frame data, including after late motion enable. Empty or hidden-only no-upload passes do not initialize that state.

The motion fixture uses a fixed public custom AABB enclosing every instance in all tested stages, including off-screen instances. This keeps the first visible frame independent of automatic-bounds dirty notification timing. Automatic AABB behavior remains covered by the separate original resource fixtures; it is not qualified by motion pixels.
