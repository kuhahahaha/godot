Finding: version_owner.free(p_version) destroys Version and returns its slot to
the thread-safe RID allocator. The old code then reads version->mutex twice.
These reads occur after the original Version lifetime ended; concurrent slot
reuse can replace the pointer with a newly created version's mutex.
RID_Owner<Version, true> locks allocation/free; RID_Alloc::free unlocks after
publishing the freed slot. version_create uses the same owner and allocates a
fresh Mutex before inserting the new Version. This proves the reuse hazard,
not that any specific application interleaving has occurred.

Fix: save the original Mutex* before locking/clearing/freeing Version, then use
only that saved pointer for unlock/delete after RID free. Map removal, embedded
set removal, _clear_version and RID free ordering remain unchanged. No public
interface, authority, scheduler, test hook, or new test was added.

No deterministic race reproduction, sanitizer result, GPU run or new test result
is claimed. Root owns builds and regressions. This file is static source evidence.
