## Actual finding to resolve

**P1 — known no-effect checked append failures cannot settle in finalization.** At first-insertion `rendering_device.cpp:10613`, `_native_height_ranges_prepare_finalization()` closes each range, calls `_native_height_range_observe()`, and returns on any error before invoking explicit range return. `_native_height_range_record_depth_clear()` stores `append_error` when original checked begin fails before any actual effect; observe later always returns that append error. Thus a proven empty/no-native failed append can never reach return in the finalizer, although `_native_height_range_return()` already permits a closed no-effect cell and FINALIZATION.md §4 promises rejected-before-effect settlement. The exact failed error must remain recorded, but an original owner proof of no effect/no unknown prefix/no graph/source obligations must allow settling that same cell. Partial/uncaptured/unknown effect must still refuse. This was immediately reported to root and the implementation owner; fix/verification is pending, not claimed here.

**Caller-repeat concern withdrawn after complete entry-point inspection.** An initial warning that `_flush_and_stall_for_all_frames()` lacked an overall phase could imply repeated graph end/issue was too broad. Original `_end_frame()` already checks qualification_graph_closed/qualification_segment_closed before actual graph/end-segment work; `_execute_frame()` checks fence_signaled; `_recording_error()` refuses external recording into a closed graph. These guards prevent the direct replay inference. Root and author were immediately corrected. Keep actual getter/swap/bounded retain-BUSY counter tests; do not add a global cursor solely on this withdrawn reasoning. The separate post-drain finalization phase remains a valid narrow design because its explicit range returns can be BUSY after ordinary frame drain.

- Scope is a single exclusive standalone D32 clear pass per range, not full height producer, E09, worker/hidden-copy coverage or Scene content authority. Existing original private API can record actual begin/clear/end results without a replacement issuer. Pending-clear, view/fallback, worker, external-access and foreign production/qualification attachments are explicitly refused before append. - Existing NativeDisposalWork already has RETAIN/POLL/RELEASE receipts. `_native_disposal_charge()` temporarily installs the caller budget and restores prior pointers; `_native_disposal_admit()` charges the current bounded service context and is unbounded on ordinary engine paths. A new reducer must use these actual admission helpers before each driver retain/poll/release; it must not invent a budget ledger or an E05/U08 claim.
- The original common QualificationSourceAdmissionScope safely becomes a no-op native-serial admission when the frame has no qualification tickets (`gdextension_qualification_rd.cpp:367`). The new range need not mint a ticket or alter this scope. Existing hidden Frame observations remain owned separately; first slice cannot opportunistically join them because they share a frame.
- Original graph resolution maps begin/clear/draw instructions/end of one closed list to its real command index; both slot and exact command-buffer resolvers validate actual begun buffers. Every saved actual handle must be resolved, not just a representative/tail. A first-slice proof that all handles map to one slot supports source capacity from MAIN_SLOT(1); a multi-slot mismatch must fail closed rather than silently exceed that source capacity.
- New prepare derives graph capacity from actual result arrays and source capacity from original native_issue_bound; source edges use checked multiplication. One range stores unique original source serials and graph→source edges; same serial must have consistent original completion/queue/issue/error facts. Multiple ranges in a shared native batch must retain separate observer obligations. Current reducer checks these consistent facts and preserves overflow as uncaptured_prefix, which must block original frame recycle.
- Empty BUSY report is no attempt; original issue loops must retain their slot cursor. A nonempty actual prefix is attempted once even when retain is BUSY. The new issue helper's retain BUSY must not cause caller reissue. The original Frame report remains source owner until both independent ordinary and bounded retain barriers succeed. Both hooks must be installed before all source-owner recycle, hidden release and fence retirement paths.
- NativeCallFact is immutable source evidence. Completion must poll that exact serial and match its exact completion_serial. IssuedUnknown may refine only through that same source's original resolved_issue=KnownAccepted callback; an unrelated final fence can never promote it. Preserve original raw issue error separately. The first inserted observe reducer rejects `source.original.error!=OK` and its clean predicate requires issue_error=OK, so its positive refinement test currently only models IssuedUnknown with raw error OK. The author has been asked to explicitly distinguish real non-OK unknown issue from known rejection rather than washing an error through a callback; final source behavior and tests remain to review.
- Frame index/epoch are exact enrollment keys, not completion facts. RD cell pool plus original Frame refs protects client Ref drop until sources are retained. Frame reuse may drop its range refs only after retention; original RD retains unresolved/returned-state cells until explicit return. Source rows/cached completion must not be reset with the Frame. Early Ref drop prevents UAF, but an operational path must still drive eventual return/pool reuse; mere RD retention is not reclamation evidence.
- The current return reducer charges release, preserves cursor on BUSY, marks each returned observer once, removes same-cell RD/Frame refs only after all returns, and keeps cached native_complete in the client Ref. No destructor driver call is added. Return must remain refused for actual unknown/uncaptured prefixes, while known no-effect close uses a distinct terminal state rather than synthetic native_complete.
- FINALIZATION.md correctly preserves original destructive wait/worker fail-stop on real failure. Post-drain release BUSY must retain driver/source cells and native_finalization_returned=false, skip already-drained phases on retry, and only proceed to graph/resources/driver teardown when actual range obligations settle. Existing LAST_REF require_close_success provides process fail-stop if unresolved finalization would fall through C++ destruction. This is not a device-loss-to-completion shortcut.
