## Real producer and observation

The GDScript host creates a normal SubViewport/world/BoxMesh/unshaded material/orthographic Camera3D, updates native transforms, sets UPDATE_ONCE and calls RenderingServer.force_draw. Actual force_draw binds RenderingServer::draw; threaded RenderingServerDefault queues _draw in the same RT command stream used by call_on_render_thread, while single-thread mode executes on the real renderer thread. Each observe callback is queued after the corresponding real draw and its stage acknowledgment is awaited before next image/action.

camera_native_register invokes original viewport_register_presentation_key on RT with a test-only source key. It does not supply CameraData, construct RenderDataRD, call render_scene, issue view/grant/accepted authority, mutate an opaque pin/action, or relax original gates. The observer directly reads viewport_owner and checks captured_camera nonnull before copying any Ref. It never calls viewport_get_camera_capture_ref; that lazy getter would create the cache and invalidate the detector, but is absent here. In the fixture process, the real common RD retention call is therefore required to populate the inspected cache. Parent planned removal/restoration of that exact call is the appropriate causal negative control.

The first real draw is unregistered and must leave null cache/invalid token. Registered stages1/2 require real viewport, already-populated production cache, exact selected/payload RID, complete tuple matching current token and actual data, presentation sequence, expected moved transform, mono orthographic payload and copied projection consistency. Stage1 keeps old Ref; stage2 requires a different capture object/token and increasing native ordinal, changed current camera transform, unchanged retained old transform/projection and original presentation sequence. Invalidation uses the original viewport entry; free is actual SubViewport.free before finish callback. Final checks require viewport owner absence and old Ref payload/token/RID identity survival, then explicit RT unref. No freed RID is dereferenced.

This does not independently observe RenderDataRD custody during a backend draw pass; it witnesses the common RD retention side effect plus original camera/cache lifetime. CPU retention tests and source chain review cover the complementary object custody facts. Stereo is outside this mono GPU fixture and remains covered by CPU source tests.

## Runner gates

run_native.py requires both real Metal startup lines with the selected Mobile/Forward+ backend and device, exactly one JSON report, stage4 and pass true, all24 required check names present, and every extra check true. It requires authority marker, exactly three unique image paths contained beneath the resolved backend directory, actual PNG/IHDR dimensions128x128, saved flag, bounded nonuniform raw-pixel count, positive native draw calls, valid SHA256 strings and changed first/second raw hashes. Process must exit0 within90s and output must contain no ERROR:/WARNING:. Script internal total-stage deadline is30s. Missing class/device, script/engine diagnostics, timeout, missing checks or process/exit failures therefore cannot become matrix PASS. Both renderer cases must satisfy the gate.

The PNG verifier checks the header/dimensions; SHA256/nonuniform statistics are reported by the actual GDScript GPU readback, not independently recomputed by Python from decoded PNGs. It also does not enforce PNG CRC/IEND or raw image digest correspondence. This is a nonblocking evidence limit for the trusted fixture process; if artifacts need independent integrity certification later, decode/recompute them and preserve encoded-file hashes. Timeout output is printed but not saved to per-backend run.log in the timeout branch; parent outer log should retain it. Neither limitation weakens the cache-population removal detector itself.
