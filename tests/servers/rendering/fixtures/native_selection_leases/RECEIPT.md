# Original native selection leases

Adds explicit original MeshStorage and MaterialStorage CPU selection leases. Mesh leases preserve the original surface order and prevent mutation/free or instance creation; material leases also retain their original shared shader and prevent mutation/free until the final release. These counters remain separate from physical native holds and allocate no VA, shader version or pipeline. They are intended for the pending public Instance192 Create transaction; the public profile gate remains.

Focused original-owner fixtures passed7 cases/2352 assertions, exit0 and no diagnostics. They cover stale generation/occupied lease refusal, independent mesh/material/shared-shader saturation with no partial increments, real shared shader across two material RIDs, original mutation/free refusal, valid external append refusal with an unheld same-descriptor positive, and actual dirty material queue service deferred until final return and replayed exactly once. Explicit saturation uses controlled private fixture counters, not invented admitted custody. Combined regression passed203 cases/90436 assertions, exit0; only the existing three pipeline failure, three foreign-camera refusal and invalid UTF8 negative diagnostics appeared.

The first build exposed an omitted explicit texture-index test argument; corrected before the successful builds. Reviews found and resolved an omitted external append gate and missing material-state refusal assertion. New API tests cannot compile against the pre-feature baseline; this receipt makes no original-baseline red/green claim for the new API. Source identities, exact commands/binary hashes/build logs and independent reviews are retained.

CPU/dummy fixtures do not establish real renderer initialization, GPU use, arbitrary cross-thread mutation, direct RD-buffer protection, failed Create prefix drain, or public Instance192 readiness. Those remain in the active queue; original physical holds are still required for later native passes.
