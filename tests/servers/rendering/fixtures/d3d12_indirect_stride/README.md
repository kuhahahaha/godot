# Ordinary D3D12 indirect stride source-body controls

Run `python3 tests/servers/rendering/fixtures/d3d12_indirect_stride/run.py --out /absolute/new/evidence` from this tree. The runner extracts the complete two ordinary production method definitions verbatim into a temporary translation unit, compiles and executes them with a mock D3D command list, then removes both generated source and executable. `harness.cpp.in` is deliberately not an engine test translation unit. A source-ref regression control accepts `--source-ref <exact-old-commit>`; it exercises those old complete methods against the same oracle and must fail the padded-address checks.

The mock `ExecuteIndirect` uses the actual selected mock signature ByteStride (16 for draw,20 for indexed) to decode every command, records all call arguments and checks bounds. Literal expected starts distinguish legal36-byte draw buffers at0/20 and44-byte indexed buffers at0/24 from the old incorrect0/16 and0/20. All command words are compared, not just addresses. Controls also cover packed single-call batches, count0/1 original single-call behavior, nonzero offsets, offsets beyond32 bits and three padded commands. Both enhanced-barrier modes require the original vertex binding once and legacy transition/flush exactly once when appropriate:28 total cases. Unused-parameter warnings are disabled specifically because the unmodified defective production methods ignore p_stride; the remaining syntax warnings are errors.

This is a CPU mock/source-extraction mechanism test, not Windows or D3D12 GPU execution. Actual Windows CI compilation does not prove GPU behavior. The two count-buffer indirect virtual methods are excluded and their stride handling remains unresolved; this fixture does not certify all four methods. It also does not test RD admission/overflow arithmetic, renderer adoption or command signatures created by an actual COM device.

Each evidence directory is new and preserves full compile/run stdout/stderr, return codes, extracted-method hashes, full production-file hash and a raw manifest. Tests allocate no host, engine build, native device or COM object. Old RED evidence must remain after production fixes. Compile failures are separate from target assertion failures.
