# GradientTexture1D native GPU image oracle

This standalone fixture compares direct E22 native snapshot final bytes to the independently generated ordinary `GradientTexture1D` image uploaded through the rendering server. Single/double Metal Mobile and Forward+ runs at the pinned2919 native checkpoint each pass270 combinations and372870 checks; the preserved raw receipts remain the authority for that scope.

The script creates each actual Gradient and wrapper through their public APIs, lets the wrapper's original deferred `update_now` complete during two frame boundaries, then calls the native plan/snapshot on the main thread. Only after capture, it performs the first `RenderingServer.texture_2d_get` read for that RID and compares every RGBA8 or RGBAF pixel byte. The image is not generated by the snapshot. The fixture checks full native status, tuple, pixel count, format, dimensions, output size, point count, scratch=0 and `real_t` width. The 4096-point descending and duplicate/unsorted inputs exercise normal image generation; deferred image upload may sort them before capture, so this fixture alone does not prove that snapshot itself sorted an unsorted gradient. Capture allocation metrics, source mutation, and signal tests belong to the CPU fixture.

The fixed matrix has widths 2/33/4096 × five point profiles (empty; one positive overbright `Color(1.5, 0.5, 4, 2)`; ordered three points; unsorted six points with duplicate offsets; descending 4096 points) × three interpolation modes × three color spaces × HDR/LDR: **270 cases, 372870 checks, zero failures per renderer**. Each case records its input tuple and every mismatch includes pixel index and both actual byte strings. Runner independently validates the exact set of 270 successful case tuples, not just the totals.

```sh
python3 tests/scene/fixtures/gradient_texture_snapshot/run_image_probe.py \
  --godot /absolute/fixed/editor --core /absolute/matching/godot/worktree \
  --sdk /absolute/matching/godot-cpp --precision single \
  --engine-receipt /absolute/successful-engine-build.json \
  --sdk-receipt /absolute/successful-sdk-build.json \
  --api-receipt /absolute/successful-engine-api-dump.json \
  --output /absolute/new-output-directory
```

Run the same command with `--precision double` and the corresponding double editor, SDK and receipts. Each invocation runs Metal Mobile and Forward+; the two invocations together constitute the required four paths. The single and double SDK build receipts must each record the explicit `precision=single` or `precision=double` command, the successful build and exact archive/API hashes. The API dump receipt must match that precision and both before/after editor hashes. The engine build receipt must have successful/stable binary and equal source-before/after maps; sources and SDK headers are checked again after both runs. The receipt is a check of the supplied files; preserve the actual full build logs/provenance separately.

The runner creates a fresh result directory containing exact compile/run commands, dependency and input hashes, SDK headers before/after, complete logs, frozen expected counts, timeout/exit status and `RESULTS.json`. It requires a non-editor process with main RD, actual requested Metal renderer, both exact case matrix and exact count, zero diagnostics/leak markers, and stable inputs. Missing main RD returns 77 and is not a pass. No main-RD `submit` or `sync` is used. Build and runtime timeout are recorded as failures. The runner's default compile is a small standalone extension; it never builds the Godot engine.

This fixture is an ordinary resource/image check. It does not establish E20 capture association, U08 budget, original E04 source ownership, ANGE production integration, Ready, G1, physical retirement or GPU scheduling semantics.
