# Original System scalar native correctness runner

This independent runner accepts the explicitly supplied new host, generated SDK header and closed seven-field `CoreBuildSelection`. It contains no fixed old host or core stamp. Old logs and containers are not reused.

```sh
python3 run.py \
  --host /absolute/path/to/new/editor.arm64 \
  --sdk-header /absolute/path/to/matching/gdextension_interface.gen.h \
  --selection /absolute/path/to/new/CoreBuildSelection.schema1.json \
  --driver metal
```

Use `--driver vulkan` for a separate actual Vulkan process set. Default `--cases all` includes the three explicit controls from `negative_cases.json`; `--cases original` runs only the two original native cases. Missing control adapters refuse an `all` runtime launch before GPU work. `--metadata` defaults to `HOST.controlled_build.json`; `--output` must name a fresh directory. `--prepare-only` hashes and snapshots the supplied files without running the host, compiling a DSO or starting GPU work. It still requires the actual final files; nonexistent future SDK paths do not silently fall back to an old header.

The probe reads, prints and checks `Engine.get_version_info().controlled_build_identity` in its synchronous script constructor `_init()`. Main attaches this script before synchronous SceneReady callbacks, so even an expected process-isolated `_Exit(0)` in those callbacks occurs after the actual identity marker. `_initialize()` only performs the ordinary loop marker/quit; moving identity back there is rejected by preflight and the regression test. `verify_identity_order.py --source-root /absolute/Godot/source` records the actual engine call order and hashes without executing a host.

Before execution, the runner checks actual host SHA and size against the available controlled metadata and compares its exact selection with the supplied selection. It rejects linked `libgodot` hosts because they require a separately pinned core. Every host launch must emit the selected actual Engine controlled identity and exactly one matching backend startup line with Forward Mobile. Input files and host bytes are rechecked before and after launches. The caller must supply the header generated by the matching build: a recorded header hash alone is not an independent attestation of how that header was built.

The two original native cases are deliberately retained without expanding similar scenarios:

- `positive.cpp`: original System scalar record, asynchronous native facts/readback, exact `0x40400000`, internal set and original unit/storage physical retirement and acknowledgement.
- `post_submit_close.cpp`: first observe an actual native issue fact for the retained ticket, then close the original bridge while that ticket is still live, refuse new allocation, cancel and drain that same ticket, preserve the copy destination and original cleanup/acknowledgement path.

The positive C++ source is a verbatim copy. The close source preserves its original baseline as `post_submit_close.original.cpp` and makes one necessary correction: record return is no longer treated as submission. A bounded observe/facts loop requires an actual semantic4/5 native issue fact, with issue=1 and nonzero native/completion/queue serials, before bridge close. A stale report revision is retried on that same ticket. If natural native completion already made the result immutable, the case verifies the original completed-result/cancel-busy rules; otherwise the same ticket cancels/drains without copying output. Both scheduling outcomes retain exact original retirement and acknowledgement. `SOURCE_PROVENANCE.json` records baseline source paths/hashes and the modified close source hash. The local standalone Godot `Error` enum is a verbatim header copy. The SDK is intentionally absent from this directory until a specific header is provided; each actual run snapshots it under the C++ sources' original include filename. Container generation and every DSO build happen afresh under the result directory. Each result contains complete commands, raw stdout/stderr, source/header/metadata/selection snapshots, DSO/container hashes and artifact sizes. Inputs from old result directories are never used to sign the supplied host.

All inherited `GODOT_SYSTEM_SCALAR_TEST_*` and DYLD override variables are removed from ordinary child processes. Controlled negative variables must be supplied only by the corresponding explicit case adapter, rather than inherited from the shell. The explicit `negative_probe.cpp` / `negative_cases.json` adapter supplies exactly three controls. Unknown and set-retirement-error cases require the corresponding TESTS-only original-owner injection marker plus the exact driver diagnostic; exit zero alone is insufficient. Global `ERROR:`, assertion, crash, leak and fixture-fatal checks always apply and are merged with each case’s additional forbidden patterns; a negative configuration cannot disable them. These two cases deliberately end the isolated process with retained/quarantined ownership and **do not** claim physical retirement, acknowledgement or DSO unload. The runner refuses a contradictory process-isolation/retirement claim. The same capacity case runs on Metal and Vulkan with a normal legal 16KiB request, then proves successful small-request recovery and cleanup on the same original context/backing. Its declared finite prerequisite is the real shared source-slot rejection before either backend profile: graphs=513, frames=514 and `slots=current_commands+514*(workers+1)>4096`. This Mac has 11 workers, so even current_commands=0 requires 6168 slots. The runner parses actual current/workers/graph/error trace values and recomputes that prerequisite. A missing/ambiguous trace, unexpected error or a smaller actual worker pool that does not exceed capacity fails explicitly; it is not reported as unsupported or accepted through a different backend error. Both drivers must report exact error5/reason19 and zero ticket/facts for this finite prerequisite. Every case records which environment variables were explicitly supplied. Actual coverage remains not-run until executed against the new matched host/SDK; prepared adapters are not passing native evidence.

Preparation validation:

```sh
python3 test_runner.py
python3 run.py --help
```

The nine Python test groups cover strict selection, actual startup/identity parsing, duplicate JSON fields, explicit negative adapter validation inherited environment isolation the actual shared capacity prerequisite, constructor-time identity placement and immutable global fatal checks for negative controls. These commands do not execute a host or compile native code. New GDScript parsing, DSO compilation and GPU execution remain pending until the root's matching host/SDK build is available. A positive result here qualifies the named original Godot native boundary only; it does not establish ANGE World/Host caller connectivity, B4 output consumption or whole product acceptance.
