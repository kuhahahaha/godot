# Current contract and source mapping

The contract distinguishes successful OS close from actual image replacement. `contracts/device-exit/ORACLES.md:29` O6 requires an actual OS call plus OK for dynamic Closed; it does not define Closed as a destructor-before-manager-return timestamp. Current manager calls `_close_library` before erasing its map entry (`core/extension/gdextension_manager.cpp:273`); `_close_library` enters NativeCloseScope, calls the original loader, observes the return, then detaches (`core/extension/gdextension.cpp:1188`). The dynamic loader calls OS close between original attempted/returned observations (`core/extension/gdextension_library_loader.cpp:327-329`); `drivers/unix/os_unix.cpp:1075` calls dlclose and returns OK only if it returns zero. No image-removal query is implemented by these facts. The native logs therefore do not show that core skipped OS close or falsely acknowledged a holder.

`FR_particle_device_exit_PROTOCOL.md:93` separately requires all callback/holder returns before CLOSE_BEGIN and inventories OS finalizers as a synchronous close phase while mapped. TLS/static/ObjC hazards remain owner qualification gates at line91; raw TLS routes remain unsupported at line374. This experiment's destructor marker is a test observer, not proof that every production SDK static finalizer is registered or qualified. No full G1/finalizer census acceptance follows.

`FR_particle_device_exit_PROTOCOL.md:408` fixes the sticky guarded claimant for one image instance. Same-retained-image reinitialization is explicitly unsupported; ordinary dynamic reload assumes that the old image actually unloads and a fresh image starts fresh statics. Therefore accepting manager result0 cannot authorize clearing claimant or reinitializing retained SDK globals. A delayed/unremoved image remains an actual reload qualification gap. The existing SDK Wrapped header already identifies native macOS TLS as an unloading obstacle; this controlled three-run comparison identifies active_guarded_user as the operative native TLS storage in the tested hot-reload profile.

Disposition: preserve the original core OS-close/result semantics and sticky-claimant policy. The SDK owner must remove native TLS retention while preserving per-thread active context, then validate real fresh-image reload, thread isolation, same-thread reentry refusal/reset and the original unscheduled-holder negative. A plain global pointer is diagnostic only. This package neither redefines G3 nor adds an unload service.
