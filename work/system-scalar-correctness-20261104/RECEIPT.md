## Changes

- System append finish consumes CheckedRecordAppend::Unknown. It marks mapping_failed and observation_dirty, preserves the first error, and lets original publish close suffix admission, expose possible_count/Unknown, and retain all resource/physical/metadata obligations. - System admission calls the existing qualification_native_capacity before ticket allocation, serial consumption, bridge publication, uniform-set creation or dispatch. Its function body is unchanged and now visible within the existing private implementation namespace. No public API, issuer, registry or caller authority is added.
- The System wrapper requires download staging blocks >=32 bytes and bounds graphs by 1+ceil(readback_bytes/32). _buffer_get_data_async at rendering_device.cpp:1544 resumes from issued_size; :1548-1555 emits one graph per copy region and advances issued_size; :1560 requests alignment32; :1562-1565 returns Busy after publishing only already-recorded regions. _staging_buffer_allocate at :960-980 supplies at least32 bytes for every nonfinal region when block_size>=32. Remaining <32 can occur only for the final region. Continuations never replay prior bytes/graphs; retries without regions do not grow the graph set. One extra graph is the System dispatch. The original shared capacity policy budgets graph_bound+1 frames, current main command slots, and hidden workers in every continuation frame, then asks the actual driver's qualification_native_call_bound_for_profile. Zero/unsupported, overflow and over-capacity bounds refuse admission.
