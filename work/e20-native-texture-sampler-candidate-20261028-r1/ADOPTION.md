## Proposed root decision

Adopt the full following package or return concrete revisions before production work. Add a typed **V2 create and scoped backing query** to the SAME `QualificationBridge::Storage` children and SAME `MainRDStorageTransport` cells. Each buffer, texture or sampler is one existing storage part and has exactly one original physical cell and one V1 retirement obligation. A texture+sampler pair is two parts of one StorageOwner allocation; no separate E20 registry, DeviceSession, native ticket, completion source, resource owner or private free path.

V1 ABI names, struct sizes, behavior and opcodes remain frozen. V2 types and function signatures are complete in [ABI_CANDIDATE.h](ABI_CANDIDATE.h). V2 explicitly validates `{abi_version=2,struct_size=sizeof(the_outer_type),reserved=0}`. Existing V1 uses its historical header-size rule unchanged. No V1 output is widened in place.

The supported typed profile is intentionally exact: owned 2D `DATA_FORMAT_R32G32B32A32_SFLOAT`, one layer, one mip, one sample, identity swizzle, no format override, no shareable formats, no imports/shared slices/resolve/discard/transient; sampling + storage usage. Width and height must fit the actual device limit, checked multiplication `width*height*16`, and the existing 256 MiB per-part bound. Sampler is min/mag/mip NEAREST, repeat U/V/W CLAMP_TO_EDGE, normalized coordinates, anisotropy off, compare off (`COMPARE_OP_ALWAYS`), lod min/max/bias=0. Map wire enums explicitly; never pass wire values as RD ordinals. This is an internal profile, not a new public RD authoring API.

Sampler logical payload size is zero; metadata and its storage-part quota are still charged. Do not invent one-byte GPU buffers to make the old bytes-only owner accept it. C must add typed part accounting to the existing StorageOwner/transport, preserving old buffer calls as a descriptor wrapper. Source retention is the existing original borrow. Existing 128 child tombstone behavior until bridge close remains bounded and unchanged; exhausting it is a quota result, not unbounded reuse or a second array.

### Content and source authority

Creation is **empty** with no initial data/transfer worker. This avoids the existing `texture_create` partial upload/null-return ambiguity. C's original qualified producer must write the image through a captured compute dispatch before TextureLoad consumes it. Sampling an empty-created image is rejected. Texture allocation view starts `view_version=1, content_version=0`; parent identity denotes the owned allocation itself, actual `Texture.owner` remains null, color mip0/layer0/count1, byte extent `[0,width*height*16)`. This root-only profile has no mutable view reassociation.

Original RD qualified producer append increments content version exactly once when its original graph record handle is valid and its write range is closed. Reserve the next version before append; overflow rejects before effects. Store original producer ticket/ref/record handle with the Texture metadata and pin its physical cell through that ticket. The next same-image write is refused while an earlier producer/consumer has not physically retired. An append with unknown effect does not publish a usable content version: mark content invalid, retain the object/ticket, drain known effects, and fail the consumer. Content version is an original append identity, **not** a completion assertion. A consumer either captures an explicit producer→consumer graph synchronization edge on the same live graph, or requires the original producer ticket to be physically retired; otherwise fail before consume append. B owns this graph/ticket join; D provides metadata and exact allocation identity only.

At source admission, B/C must bind the original typed StoragePartBorrow and scoped native backing ref to exact allocation generation, physical backing serial, view version, content version, descriptor, parent, subresource and range. Compare against original RD state at RT execution, not just an earlier copied query. `storage_backing_v2` only snapshots this original child state; it grants no lease and never promotes RID numerics into source approval. No public API may set content version from caller data. C04/K04 selected attachment/source approval still owns its original source allocation/view association and static proof. This new owned E20 image does not impersonate a selected depth attachment or repair unknown import/view provenance. All native proof tuple fields remain tied to their original issuer.

### Driver allocation failure rule

Original known objects always retire through the original RD frame list and last driver return above. Failed creation before GPU use may roll back native allocations synchronously **inside their original driver create implementation** because no RD object/graph has been published; this is not a substitute for ordinary successful-object retirement.

Source finding needing explicit root decision: Vulkan `RenderingDeviceDriverVulkan::texture_create` at `drivers/vulkan/rendering_device_driver_vulkan.cpp:2418-2428` creates an image in the extra-memory-tracking branch, then returns on VMA allocation/bind failure without explicit earlier-image rollback; the subsequent image-view failure branch `:2461-2472` does roll back. Complete candidate includes a scoped rollback guard in that same original function: destroy `VkImage` after memory allocation failure; destroy image then free VMA allocation after bind failure; disarm guard only after `TextureInfo` is published. Do not classify these current partial native failures as no-effect until repaired or gate that tracking mode Unsupported before creation. VMA normal `vmaCreateImage` failure and `vkCreateSampler` failure return no published original object; fault-inject their cleanup contract during implementation tests. Metal original texture create `drivers/metal/rendering_device_driver_metal.cpp:563-584` rolls back its buffer/TextureInfo when no texture results; original sampler create `:946-1000` returns retained `MTL::SamplerState`. Real frees are original Metal `texture_free:737` and `sampler_free:1003`, and Vulkan `texture_free:2641` / `sampler_free:2842`. No backend-specific completion registry is needed.

If a new driver path cannot prove known-zero or known-live after failure, retain original child state2 and the actual known partial allocation objects in the original native create owner; publish no usable backing and no physical-return success. That path requires an original driver resolution/disposal result before release. This exact profile removes the RD upload-induced ambiguity rather than hiding it.
