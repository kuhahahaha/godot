# Qualification pin lifecycle source audit

Scope: author source review of current D ticket count pins, physical reverse references, cancellation and acknowledgement. This is not an independent review, executed regression, GPU proof, or production acceptance.

The original zero-effect reducer can return count pins while a prepared ticket remains open. `_qualification_unpin_resources` clears `resource_pins`, making a subsequent `_qualification_pin_resources` increment a fresh count rather than mistake a historical RID for a live pin. Re-pin checks the physical cell bridge and `use_closed`; upload additionally requires the original E05 child to remain neither retiring nor acknowledged. A reserved RT operation retains the ticket via `accepted_rt_refs`; it does not grant permission to bypass those later destination checks. Cancelling closes admission, while release continues to require returned physical ownership and no accepted RT/frame/recording references.

Physical reverse references deliberately survive count unpin. Retire checks the original ticket physical-return flag. Ticket/child acknowledgement decrements bridge/private ownership but preserves allocation until bridge destruction, so those retained pointers are not freed by individual acknowledgement. Bridge destruction requires all children acknowledged. No production defect has been established in this reviewed sequence; no production change is proposed from this audit.

Existing source controls cover zero-effect count re-pin, accepted RT cancel/refusal/release, and physical-return enqueue windows separately. They do not, by themselves, execute the combined sequence of zero-effect return, E05 storage retirement, later admission of that same prepared upload, and original bridge teardown. The next useful coverage is that combined original API sequence: a later upload must refuse the retired original child with no new graph/native effect, while all existing ticket/RT references still release exactly once. This is a coverage gap, not an observed defect or a new owner blocker. Do not call the existing separate tests an end-to-end proof.

SOURCE_MANIFEST pins reviewed bytes. SOURCE_TRACE records exact anchors; anchor presence only supports source navigation. No existing runtime controls or shared builders were rerun. Complete matching SDK/archive/DSO, wrapper cohort, canonical actor, same-request completion/readback, and G1 gates remain open under their existing owners.
