# RenderingDevice parent cascade reentry — 2026-10-30

A framebuffer's invalidation callback can synchronously request `free_rid` for the texture parent whose dependent cascade is already running. Before repair, the nested request freed that parent before the outer dependency traversal returned. The controlled child process observed the parent no longer owned inside the callback and exited 86 with `RD_CASCADE_PARENT_FREED_BEFORE_OUTER_RETURN`, before the outer traversal could access its invalidated iterator. The corresponding non-reentrant control passed 1 case / 5 assertions. This is a bounded pre-danger RED, not a crash-as-success.

Local commit `34f8d55c61` tracks same-device, same-render-thread RID frees already in progress and coalesces a nested request for that exact RID. It re-finds the parent dependency entry after each dependent free, because synchronous callbacks can mutate the map, and stops parent destruction if a dependent remains linked after its free request. The valid and nested-parent controls each passed 1 / 6, and a sibling callback control passed 1 / 7 while freeing both siblings exactly once.
