# Metal size-table backend source review

Reviewer: root, separate from Astra implementation and Sol helper reviewer. Reviewed the seven final production files locked in REVIEWED_FILES.json. No blocking source defect was found in this finite backend repair. This is source integration review, not an executed repaired Metal driver or GPU acceptance.

The translator reserves the synthetic table after the complete reflected ordinary argument range, for each storage-buffer set and every relevant stage. Runtime layout derives from that same range whether or not the creating shader uses length. Existing ARG and SLOT metadata are both populated even for direct shaders; ordinary direct no-length creation therefore retains a nonzero ordinary layout and is not accidentally rejected by the added table calculation. Direct length and unsupported buffer descriptor arrays reject during container generation.

The two BufferInfo allocation sites are both within buffer_create and both receive the original requested logical size. Dynamic derived frame stride remains separate; the base MetalBuffer assignment does not overwrite it. Storage/uniform set byte lengths are narrowed only through the checked helper. No size uses MTL allocatedSize or the full persistent ring.

Static pointer/table bytes share the original argument MTLBuffer. Allocation failure and failed address construction do not publish a set; the latter frees the allocated buffer through the existing allocator. Existing copy-queue upload and uniform_set_free own the entire enlarged allocation. Render and compute dynamic paths copy the template, rebase the self pointer using the actual ring allocation offset, update the ordinary dynamic buffer addresses, and explicitly mark the indirectly addressed containing buffer read. This introduces no separately owned auxiliary allocation or new retirement queue.

Metal format4 is emitted through the existing virtual format-version hook. The shared production header gate checks exact format/version, rejecting old format3 bytes. Old native libraries for unchanged no-length source still receive the compatible ordinary argument prefix; length-using generated MSL changes its source hash and cannot reuse the old failing source key.

Root independently verified all seven production hashes, 56 implementation artifact sizes/hashes and 26 helper-review artifact sizes/hashes, and checked the final production diff for whitespace. Author evidence reports 26 matched source/translator/layout outcomes and three actual Metal TU syntax checks; Sol independently replayed helper canaries, u128 address boundaries, ASan/UBSan, targeted mutations, descriptor-array refusal and selected translator slices. These are not whole-engine or native-MSL compiler executions.

Outstanding: new engine build and complete container use; native Metal pipeline creation and dispatch; strict nonaligned logical-size controls; both shared-set directions; dynamic/ring paths and allocation-failure injection under a real driver; ordinary rendering regressions and physical retirement. Vulkan remains a separate aligned control because its existing descriptor range is rounded. No B4 source authority, renderer/adoption or whole-family qualification follows from this review. The original guard shader and matched System host remain unchanged.
