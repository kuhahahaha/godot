# Native held facts: existing custody, transport seam and next slice

Source audited: `851b46b8e0ba2ed69ae44a18ab2768cc48457e13`, 2026-11-08. Read-only source audit; only this document is written. No build, engine execution, production edit, SDK regeneration, or remote message. Existing untracked work is preserved. This map follows repository AGENTS and `.agents/skills/godot-fr/SKILL.md`. It is an implementation map, not an activation or GPU acceptance receipt.

## Decision

The current engine can truthfully observe **original material RID + material generation + original compiled shader version + needs_inverse** while an actual `MaterialStorage::NativeSelectionLease` remains held on the main RD render thread. It cannot truthfully issue a generic mesh generation scalar or a full product material/profile qualification certificate today. The existing native output bank and original Production attachment/request chain are the correct custody and transport owners; a second registry or free-standing ID allocator would weaken that chain.

A complete B Ready fix is therefore not a one-line replacement of CAPABILITY. The independent resource review correctly identifies missing native facts and a separate WorldLoader `from:` input gap. The latter remains with the provider/loader owner and is not solved by a D facts proc.

## Existing bounded native owner to reuse

`ExternalOutputOwner` in `external_output_owner.h` already has:

- `generation_pin`, `generation_registry`, `generation_request`, `generation_root_serial`, `metadata_lease`, actual `device`, native output `generation`, and terminal state;
- placement-only finite `GenerationMeshSelection { RID mesh; NativeSelectionLease lease; }` rows;
- flattened `GenerationMaterialSelection { RID mesh; uint32_t native_surface; NativeSurfaceHold geometry_source; RID material; uint64_t generation; NativeSelectionLease lease; }` rows;
- explicit mesh/material/source retained-prefix counts, attempted/completed bits, and faulted-unpublished state;
- finite preparation rows indexed independently of surface/slot arithmetic. Those rows retain exact pipeline/pass/geometry/material custody; do not repurpose them as pre-Ready product evidence.

`plan_metadata_layout` / `plan_generation_selection_layout` account the row sizes/alignment in original accepted metadata. `install_metadata_directory` constructs them in place; no live relocation or elastic vector is permitted. Any additional retained POD fields must be included in layout recomputation and quote/create exact-byte checks. Prefer a synchronous projection with no retained extra row first.

`_external_create_received` (`particles_storage_external.cpp:457`) constructs the owner in the quoted metadata block and installs an independent original generation root before selections. `acquire_generation_selection` (`external_output_owner.cpp:1140`) checks that root, request equality and metadata, then retains a bounded mesh prefix followed by material prefix. A failure closes admission, marks unpublished/faulted-retiring and preserves the acquired prefix. `acquire_generation_surface_sources` (`:1203`) separately retains each original flattened surface. Source/native backing custody is independent of CPU selection and must stay so.

A future generation-bound facts reader belongs beside these methods in ParticlesStorage/ExternalOutputOwner: validate original physical context, exact registry/request/generation root, actual device, generation state and completed retained prefix; select a finite original row by checked index; project immutable facts only. It must reject foreign request/library/device, stale output generation, missing/released selection and closing/new-work states. A copied RID/generation/row index cannot retain or authorize anything. A borrowed scalar needs no new lease; its continued authority is the existing owner's validated lease and root, not the output bytes.

**Bootstrap caveat:** B's inspected Ready chain needs renderer resource facts before System Prepared. A future reader that requires an already-created output generation cannot alone close that route unless the actual preparation order first creates and retains this original generation under a valid accepted request. Establish that owner/order in the caller before wiring Ready. Do not create a second pre-Ready registry or make the main-thread metadata receiver manufacture a physical context to hide this dependency.

## Close, retirement and reuse: retain the existing chain

No new close controller is needed for a projection.

1. Withdraw/cancel seal admission and close actual owner views/slots; new facts must refuse once original currentness is lost. A pointer or cached POD copy must not reopen it.
2. Slot preparations and accepted native uses return through original finite groups/root, with immutable hold metadata and directory phases intact.
3. Generation service in `particles_storage_retire.cpp:474–566` first drives original native disposal and `generation_returnable`. It returns one retained source/CPU lease per admitted service phase: geometry source prefix first, material selection prefix next, mesh prefix last. It consumes controls/passes and checks receipts/deadline; no physical-return claim is manufactured for CPU lease release.
4. `return_reserved_cells` destroys directories as a separate charged phase only after custody is zero. Generation root returns through `production_output_generation_return`, then state becomes RELEASED. Unpublished failed owners are freed on that terminal admitted phase.
5. Published SceneOnly metadata stays until actual `particles_free`; terminal alone is not metadata return. Preserve exact request return-consume/ACK/release behavior and library CodeHold retirement. Do not free a selection bank on caller destructor/thread or reuse its row while a root/use remains.

If a future public pre-output selection holder really is needed, it must extend an existing original accepted request-owned OUTPUT_METADATA contract and bounded retirement owner with explicit accounted rows. That is a separate reviewed implementation slice, not an invented handle allocator in this document.

## Exact next executable slice (internal, independently landable)

Implement a **pointer-free internal material observation projection**, without changing any public ABI or public profile availability:

1. In `material_storage.h`, add an internal POD, for example `NativeSelectionShaderObservation { RID material; uint64_t material_generation = 0; RID shader_version; bool needs_inverse = false; }` and `Error material_selection_get_shader_observation(const NativeSelectionLease &, NativeSelectionShaderObservation &) const`. These are proposed internal names, not frozen ABI.
2. In `material_storage.cpp`, call existing `material_selection_get_shader_features` into a local. On failure return unchanged output. On success copy only original material/generation, compiled version and inverse into a local observation, then assign output once. Preserve existing ShaderRD/version coherence validation inside the existing function; no compiler pointer crosses the new boundary, no allocation/registry/counter/lease/metadata charge is added.
3. In `modules/particles_runtime_tests/particles_external_guard_test_fixture.cpp`, extend the existing real material feature cases (plain, vertex inverse, fragment inverse, alpha hash, alpha scissor, normal-only, both) to exercise this pointer-free boundary. Compare original material and original generation, exact returned compiled version and expected inverse. Sentinel output must survive inactive/released/empty-code rejection. Run both Clustered and Mobile native fixtures when resources permit; this audit did not run them.
4. Add meaningful retained-source controls: attempt original shader/material mutation while the selection is held and prove the held observation remains original under the documented refusal; release, perform successful real mutation/update, acquire a fresh selection and prove the old generation is rejected and new original observation changes appropriately. If B supplies retained resource COW, retain original A, replace source with B, observe A through A's lease and B through B's independent lease, and prove closing one does not release the other. Do not call a plain two-query equality test “COW”.
5. Keep `material_selection_get_shader_features` for engine-only physical pipeline users. This new POD method does **not** satisfy full B Ready, issue a held public token, or certify profile qualification. It establishes a truthful reusable native payload for the eventual typed leaf.

Do **not** land a mesh generation assignment alongside this slice. There is no authoritative existing owner generation to copy. A future true Mesh revision needs defined mutation coverage (surface add/remove/clear, all successful region changes, material/AABB/blend/shadow changes as appropriate to the promised meaning), checked overflow, exact retained old/new source semantics and actual consumer contract. Until that is implemented and reviewed, report mesh generation unavailable. A meaningful regression must distinguish clear/readd on the same RID and successful post-release content mutation; constant-1 and RID-derived implementations must fail it. Retained NativeSurfaceHold/COW tests must separately prove original geometry/backing survives replacement, not infer a generic Mesh version from native buffer RIDs.

## Subsequent public slice: concrete edit sites, no guessed ABI

After fixing preparation order and native qualification semantics, define a new additive JSON DTO/proc pair whose scope is explicitly original held renderer facts. It should accept actual Production physical context/request plus a checked original owner/row locator, return only native scalar observations and status, and retain nothing on a read. Use the existing receiver/callback, rooted RD leaf, Registry authentication and ParticlesStorage bank rather than introducing a “renderer facts registry.” ABI field widths/layout/version/name must be generated and reviewed from the current JSON; this map intentionally supplies no guessed C typedef or numeric profile token.

Required source edits are `gdextension_interface.json` and its generated header; `gdextension_external_output_interface.h`; registration/static_asserts in `gdextension_production_interface.cpp`; rooted leaf/extent validation in `rendering_device.cpp`; actual checked receiver in `particles_storage_external.cpp`/ParticlesStorage declarations; and owner projection in `external_output_owner.h/.cpp`. No changes to existing frozen V1/V2/V3 DTOs. A new retained payload enlarging bank rows must update exact metadata planning and quote/create recomputation, and use existing prefix retirement.

Required rejection coverage: foreign library/device/request, expired callback, closed/pending original holder, stale output generation or row, released/partial selection, dirty/invalid shader, next pass, unsupported backend/profile, overlapping/misaligned/overflowing spans, unchanged output on unsafe extents, no lifetime/charge change on failed observation, and same owner surviving bounded cancel/withdraw/retire until actual original return. Full profile success needs its own independently specified requirements and actual backend tests; compiler observation success is insufficient.
