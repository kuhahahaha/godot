## Required correction: per-resource no-hold oracle can be masked

[P2] `after/tests/servers/rendering/test_mesh_storage_external.cpp`, new `preflight_only`, around the first assignment `actual->native_immutable_holds = UINT32_MAX`: the test performs several successful preflights, then overwrites the real VB hold counter with UINT32_MAX and later zero. It never checks that counter before those overwrites. Its final `device.native_immutable_hold_count == 0` checks a different counter. An implementation defect that increments only the resource counter would therefore be erased by the test and could pass every final assertion, despite violating the method's central no-hold contract.

Add an assertion of the actual VB's `native_immutable_holds == 0` after successful/error preflight groups and **before the first counter overwrite**, then again after metadata restoration. Preserve original counter/flag values rather than assuming zero where fault injection is intended to be reversible. This is an oracle gap, not an observed counter mutation in candidate production code: the reviewed implementation performs no such increment.

## Source analysis

- Ordinary format compatibility: raw descriptor cache key and cache-hit path remain before normalization. The extracted normalizer retains implicit-binding normalization, duplicate-location/unsupported-size rejection, exclusive implicit/explicit selection and shared-binding stride/frequency equality. Driver call, cache insertion and failure sentinels remain at their original factory owner. Added generic caller diagnostics change diagnostic multiplicity, not factory result or cache state. The existing invalid-format ERR_CONTINUE behavior is deliberately retained for ordinary callers; native preflight separately excludes negative and >=MAX formats.
- Ordinary VA compatibility: scratch preparation retains default/per-binding offsets, used-binding existence, original VB ownership/retirement, complete offset+element+stride fetch-range checks, max-instance calculation, actual driver IDs and tracker/untracked/transfer scratch membership. Description assignment moves until after successful scratch preparation but before owner publication. RID creation and dependency insertion stay exclusively in the ordinary factory. No ordinary frequency/count-zero policy was silently tightened.
- Native validation: rejects zero vertex count, invalid format and non-VERTEX/non-INSTANCE frequency; structurally normalizes and checks exact fetches before direct leaf eligibility. uint32 stride/count multiplication fits uint64; offset subtraction precedes range arithmetic. Native rejection of count zero prevents wraparound in the shared legacy per-vertex expression. Legacy instance count-zero support remains in shared preparation; the proposed helper-level assertion covers this narrow case without claiming a full ordinary factory regression.
- Eligibility extraction: reviewed original append eligibility and extracted helper; checks remain in original order and return the same errors. Hold acquisition still deduplicates and checks capacity before eligibility, traverses original closure, then increments counters/publishes its hold only after complete success. The preflight calls eligibility only for unique actually used direct VBs and publishes no hold. Its different multi-fault precedence is documented and does not change original acquisition.
- Locking/lifecycle: preflight adopts original immutable acquisition's caller render-thread, driver/escaped-device, RD mutex, active-list/callback/finalization and device-counter gates. It acquires no Surface lock. Scratch data is local; caller result is reset at entry and assigned only on complete success. No retained pointer to temporary tracker lists escapes. It is an observation at this instant, not custody or a guarantee that a later factory will succeed; caller must retain/revalidate and follow Surface-before-RD ordering.
- Bounds of proof: direct used-VB validation does not validate existing VA/IA, closure or aggregate G, detached directory, external history, future pipeline/driver format support or material/shader selection. Header/README make those gates explicit. Empty descriptor sets are not rejected by this generic wrapper; a higher-level NativeVertexArrayPlan must enforce any required surface descriptor cardinality. No current caller integration is added, so no higher-level admission claim is established.

## Tests, safety and remaining coverage

The proposed literal boundary is independent and useful: count3/stride12/element12/buffer40/offset4 is exactly 40 bytes; offset5 and UINT64_MAX must fail. Duplicate/mixed/shared-stride failures, actually-used deduplication with unused null source, native count0, instance stride0/nonzero allowance, resource saturation/escape/retirement/transfer/no-driver, missing owner, offset-count mismatch and negative enum cases exercise real candidate branches. Output vectors are guarded before access; failures use nonfatal CHECKs, and fault metadata is restored before free. The known fixed driver creates a small real RD buffer; obtaining its owner should nevertheless be checked/guarded before new test dereferences if the fixture is extended to inject creation failure. Temporary scratch tracker pointers are not dereferenced after resource destruction.

Genuinely absent direct cases in the new test: wrong-thread/no-driver/escaped-device and device-hold saturation; draw/compute/raytracing active lists, queued callbacks and finalization; persistent/device-address buffers and qualification use_closed; nonzero attribute offset, missing binding, and shared-binding frequency mismatch; checking normalized attributes/max-instance reset after an error that follows a successful nondefault output. These are coverage gaps, not discovered source defects. At minimum the finalization/active-list and persistent/device-address/use_closed refusal gates should be included in the next behavioral matrix because they form native eligibility/lifecycle boundaries. Existing neighboring ordinary tests exercise factory failure/plan routes, but the new count-zero check calls the shared helper, so it does not independently certify public factory/cache compatibility. Run appropriate ordinary factory and immutable-hold regression tests after integration rather than promoting helper checks into that claim.
