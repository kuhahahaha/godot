# Checked sink terminal reducer: independent review

Default Sol, read-only current uncommitted source review, 2026-11-08. Scope: RD checked-capture reducers, NativeHeightRange fields, sink finish/unwind, and the two new test helpers in `test_native_height_range.cpp`. No production modification, build or execution. The known outstanding worker/hidden integration is not relisted as a new finding. Source was concurrently editable; anchors below identify the reviewed functions rather than a frozen build.

## Findings

1. **P1 — finalization bypasses the new original terminal accounting.** `RenderingDevice::_native_height_ranges_prepare_finalization` (~10804) unconditionally sets each `range->recording_closed=true`, before checking `known_no_effect` or observing/returning its prefix. For checked-capture ranges, new `_prepare_checked_capture` has already set `recording_started=true` and `capture_sink`, but only `_close_checked_capture` checks `terminal_requested`, same frame/epoch, no open list, known restoration, and exact enrolled business/transfer/cleanup counts. A checked sink that never finishes/unwinds, or has an un-enrolled original result, can reach the finalization helper without those checks. In particular, a prepared range with no enrolled rows follows the known-no-effect removal path regardless of whether its original sink was terminal. Finalization must require a checked-capture range to have passed original close before treating it as closed; it cannot infer completion from missing rows or safely dereference a potentially dead sink. A guard on non-null capture provenance plus unclosed recording (or a dedicated original-close-confirmed field) preserves existing standalone clear finalization behavior. Add a direct finalization control to the new tests.

2. **P2 — unknown-cleanup test does not exercise completion promotion.** `checked_sink_failure_terminal_controls` second case (~215–239) checks `prefix_settled==false` without invoking `_native_height_range_observe`, and has no sealed/issued/completed original source to settle. The same false defaults and `give_back==ERR_BUSY` follow from `has_recorded_effect=true` even without a quarantine guard. It proves sticky business error and that an empty unknown-effect prefix cannot return; it does not prove unknown cleanup prevents a genuinely settled main prefix from becoming Complete. Extend the case with the existing synthetic sealed/issued/retained/completed positive prefix setup, then inject unknown cleanup and call observe. It should keep `native_complete=false`, `prefix_settled=false`, and release count zero. The provenance fault cases are also reducer-level test injections, not execution of the real checked End.

## Other observations

- Current close correctly preserves the first business error while marking unknown/open/unaccounted cleanup custody uncaptured; ordinary close freezes recording rather than fabricating completion.
- Cleanup admission now returns the current admission result separately from sink sticky error, allowing the original independent End attempt after a known business failure. Its normal business entry points still reject further work via `reserve`.
- Actual handle capture calls `contains_record`, de-duplicates complete identities, marks effect before validation, and preserves unsupported transfers as unreturnable rather than empty-prefix success.
- New tests use valid-looking foreign handle shape and existing test friendship consistently; no obvious static compile error found. Successful object compilation alone is not evidence these tests executed.
