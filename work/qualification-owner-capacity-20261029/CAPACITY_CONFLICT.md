## Why dropping cells is unsafe

- `QualificationBridge` has separate `storage`, `units`, `tickets` arrays of 128. Their acknowledged entries remain non-null until bridge close. Source inspection establishes the same cumulative-slot behavior for all three; the Metal run measures storage only.
- Storage create deduplicates `(allocation_slot, allocation_generation, part, create_attempt)`; native-unit create uses `(record_slot, preparation_generation, operation_serial, physical_unit)`; record/prepare uses `(record_generation, request_nonce)`, with attempt in the matched full request. An acknowledged matching key returns stale instead of acquiring another native effect. Nonidentical same-key requests reject.
- RT's `retired_operation` is a one-cell **transport** high-water mark. It does not certify a business key has not already been performed. The probe sends the same old key with a new transport operation and confirms the live tombstone is what still rejects it. Removing that tombstone while keeping V1 admission can therefore execute the old business request again. A new output serial does not prevent the new effect.
- At the measured parent `68cc717788`, `qualification_release` leaves both `ticket.physical_uses → cell` and `cell.uses → ticket` pointers; physical unpin clears live RID counts only. The current separately reviewed reverse-unlink change removes both sides after the original release gates and nonblocking synchronization, but preserves all ticket/resource tombstones. Frame refs, queued service, accepted RT refs, native observer ownership and actual physical returns must all be discharged before deletion. That unlink is a prerequisite, not authority to delete business history.

V1 accepts positive keys without a documented globally ordered business sequence or finite stale-request expiry. Under arbitrary ordering, retaining exact membership for an unrestricted set of old business keys is incompatible with recycling a fixed 128-entry history while also accepting every fresh key indefinitely. Neither QRT ordering, caller-chosen larger numbers, RID, pointer nor a digest supplies the missing issuer guarantee. Raising the array size only postpones exhaustion; clearing it or opening a bridge per occurrence violates replay/ownership requirements.

## Decision input, not an invented issuer

A viable direction is a versioned admission mode on the **original** bridge, agreed before any V1 business effect. The real existing E05/E06/R01 issuer must supply an authenticated original operation sequence or retirement epoch with explicit rules for same-operation retry, attempts, per-slot generations, bounded out-of-order work, holes, final sealing and reconnection. The bridge can then retain the full active-window identities and original children, and advance a compact closed prefix only after the issuer proves no older operation can later appear and D has drained actual graph/frame/RT/native/physical references. Any request below the closed prefix is refused; an unresolved hole or Unknown stops advancement. The exact existing owner identity and proof must be supplied by its owner; a newly caller-selected serial or a new standalone capability is not authority.

Do not retrofit that rule silently to existing V1 callers or delete V1 tombstones in a bridge still accepting V1 operations. A/B/D still need to fix the actual issuer/sequence domain, the maximum live window and legal ordering, and the exact no-effect/close/cancel/reconnect transition. Only then can >128 actual successful create/return/ack and old-reference/replay tests establish the intended solution. The real runtime observation above remains a failure boundary until that happens.

## Adjacent T1 prerequisite

Separately, current qualifying sets pin E05 storage/E06 shader cells, but Vulkan `vkFreeDescriptorSets` returns a `VkResult` which its void `uniform_set_free` ignores while frame disposal decrements those pins. The fake descriptor RED reproduces the resulting missing error channel, not a real Vulkan fault. A correct fix must retain the original descriptor/pool and every dependent cell after Unknown, avoid repeating that free, isolate a shared non-linear pool from unsafe reuse, propagate/retain the first real error, and stop destructive finalization. A proposed RD-wide sticky flag alone is insufficient: it can starve unrelated bridges, does not bound already admitted set nodes, and refusing a marked child during `_free_dependencies` can cause its parent's void recursion to spin. The broader checked-driver/set-owner T1 design must resolve original per-owner capacity, pool quarantine and recursive progress rather than silently changing ordinary unmarked resource semantics.

The independent reviewer `/root/t1_independent_review` verified source keys, the recorded real storage probe, reverse-pointer lifetimes and these two distinct boundaries. Unit/ticket >128 and any actual Vulkan failure have not been run. The long goal remains active.
