# Original ticket reverse-use release — 2026-10-29

Scope: original Godot Registry/RD ticket release; parent `68cc7177889afd1e546a835d55c23f6b68fb5b0a`. This enables one part of future safe slot reuse; it does **not** delete ticket/storage/unit tombstones, alter V1 replay, implement >128 successful operations or establish product/Ready/G1 acceptance.

At the parent, physical unpin removed RID counts but acknowledgement retained both `ticket.physical_uses → cell` and `cell.uses → ticket`. The owner therefore could not safely delete a retired ticket or its referenced cell. The changed release performs a bounded same-bridge consistency scan under the original Registry lock, rejecting null/foreign/duplicate/missing edges before any native release. Current original edge writers hold Registry plus RD; a zero-edge ticket keeps its original no-RD-lock release path. For a ticket with valid edges, release probes the RD lock nonblockingly, releases it before existing native observer callbacks, and re-acquires it nonblockingly to recheck and remove both directions before ack. If the second lock attempt is Busy, already successful native observer releases retain their existing `owner_released` progress; retry skips them and leaves every edge/ack intact until all can be settled. No child is freed and the old business-key tombstone remains.

The scan checks only the same bridge. Current production `_qualification_pin_resources` refuses a physical cell from a foreign bridge before writing either edge; a constructed cross-bridge reverse-only orphan would not be detected here and remains an explicit precondition to resolve or prove unreachable before future actual reclamation. This change does not claim robustness to that corrupted state. It does not change ordinary resources without a qualification cell.
