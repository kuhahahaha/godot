# Instance192 guard wrapper component

The wrapper prepares five actual ShaderRD variants and RD compute pipelines only when called by the main RenderingServer render thread. It admits no partial ready bundle and clears actual created pipeline/version prefixes on failure. These branches are implemented and syntax checked; **actual native pipeline creation/failure/cleanup have not run**, and driver-free completion has not been observed. No engine build or GPU run was started.

`verification.json` records exact syntax/fixture commands, rc, source hashes and raw-log hashes. Debug/tests and release syntax returned 0. The production shader component fixture (`--mutations`) returned 0: INIT/VALIDATE/FINALIZE and INIT_EMPTY/FINALIZE_EMPTY SPIR-V compile/validation/reflected layout passed; 40 sequential CPU production-control/interval cases passed; ignoring source validity, geometric bounds and valid previous history produced the required failing expectations. This establishes no concurrent GPU ordering, draw/adoption/completion or physical retirement.

Five new `[ExternalOutputGuard]` doctest cases cover bounded complete lane coverage, zero capacity without dummy records, exact extents and distinct RIDs, source accessor/options rejection, and bad request/subset refusal. **The five doctests have not run**; tests are automatically discovered by `tests/SCsub` and have a force-link declaration. Static assertions check 32-byte push constants, 224-byte proof header (accessor192/options208), 144-byte surface stride (command128).

`LayoutPlan` contains descriptors and separate INIT/every VALIDATE chunk/FINALIZE parameters only. Each phase must be recorded by the original owner with the required compute barriers; the plan does not perform dispatch or confer RecordedOrdered. The original K/E09 owner must reserve budget, authenticate source/backing/generation/material/proof, retain native uses, attach original obligations, create uniform sets, perform checked recording and retire all resources. Supplied RID/length pairs are **not** independently authenticated against RD private allocations. The preflight cannot inspect actual GPU contents.

No uniform set is created here: RD uniform-set creation can make writable buffers mutable and append graph synchronization, so it must occur under the original owner's obligations. The wrapper makes no production token, issuer, callback scheduler or qualification ticket. Wrong-thread calls refuse before resource preparation. Destruction is main-RT owner-only while native resources exist; an invalid off-thread destructor retains the shader object rather than running ShaderRD native frees off-thread. `release_pipelines` is main-RT-only and must follow original owner physical retirement; it does not prove that retirement itself.

`diff-check.log` checks each owned untracked file against `/dev/null`: rc1 means file contents differ; empty diagnostics mean no whitespace errors. Generated `.gen.h` is ignored build output created using `glsl_builders.build_rd_header` and the frozen full-tree Python fallback, not a separately authored shader.

Independent review found that the original zero-capacity six-descriptor plan could not bind the eight-descriptor shaders. `empty-layout-red.log` preserves the required failing reflection check. Dedicated INIT_EMPTY/FINALIZE_EMPTY variants now compile out both record descriptors and record functions, and the plan explicitly selects them. They still read the actual source/meta, initialize all protected commands to zero and finalize status, without record allocation or dummy particles. Empty INIT also faults a nonzero capacity. The five reflected layouts, 40 CPU cases and three expected-red mutations passed (`empty-layout-green.log`); current wrapper DEBUG/TESTS and release syntax returned 0 after regenerating its header. No linked engine, native pipeline or GPU execution was added. Independent re-review closed the finding; its source snapshots, production-plan/empty-reflection check and independently rerun fixture/syntax results are in `work/b4-guard-wrapper-review-20261104/REVIEW.md`.
