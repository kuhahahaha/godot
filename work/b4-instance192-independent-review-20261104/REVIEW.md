# Instance192 independent shader-component review

Reviewer: `/root/b4_instance192_review`. Scope: the nine Instance192 SceneShader/template/helper files, plus source inspection of the root-owned spatial inverse builtin mappings. Phase: source review and lightweight template checks only. No production source edit, engine build, linked-engine test or GPU run was performed. Formal inputs: OUTPUT_CONTRACT, BOUNDS_MATERIAL_CONTRACT and HISTORY_SOURCE_CONTRACT in the sole ANGEParticleDesign document tree.

## Finding I192-R1 — P1: global group activation rejects unrelated Native trails materials

Initial reviewed helper unconditionally emits `#error Instance192 does not admit native particle trails` when an Instance192 group is compiled with a material's `USE_PARTICLE_TRAILS` define. Both SceneShader getters call `ShaderRD::enable_group` for the whole renderer ShaderRD, not solely the selected material version. `shader_rd.cpp:943–964` recompiles that group for all material versions. Moreover `_version_set` (around 803–825), `version_is_valid` (around 873–899) and `version_get_shader` in shader_rd.h compile every enabled group on new/dirty material versions.

Thus: create/use one eligible Instance192 material, then create or modify an ordinary Native particle-trails material. Its Native stages are legal, but its globally enabled Instance192 stages encounter this #error. Freshly initialized enabled groups have null variant slots; `_compile_version_end` (around 752–793) sees those null slots and clears the whole material version's variants. The per-material `instance192_shader_supported()` guard is never called for these incidental group compiles and cannot protect Native materials. For already-clean versions whose disabled group has placeholder RIDs, initial activation still emits compile errors; immediate whole-version clearing is not asserted for that placeholder branch.

`FINDING_INITIAL_FILES.json` plus `finding-initial-*` preserve the exact initial source, including ShaderRD lifecycle implementation. `TRAIL_GLOBAL_GROUP_RED.json` records independently executed actual complete-template controls: Native trails stages compile, while the same material under Instance192 group defines fails with the intended trails diagnostic (both renderer/stages). This is template compiler evidence plus a source-proven lifecycle consequence, not a live Engine regression run.

Resolution reviewed: author removed the material-specific trails #error and documented why incidental global-group variants must compile. Both actual Instance192 shader and vertex-input-mask requests still reject trails through `instance192_shader_supported()` before enabling/looking up the group. Independent GREEN compile of all eight Native/incidental-Instance192 stages passes (`TRAIL_GLOBAL_GROUP_GREEN.json`), against the preserved four exact external-group RED stages and four legal Native controls. **I192-R1 is closed at source/template level.** Actual Engine group activation/new-material/recompile lifecycle and direct C++ refusal regression tests remain unexecuted. A negative compile alone was a false safety oracle in the initial fixture. No outstanding blocking source defect found in the final reviewed component.

## Reviewed behavior and bounds

- Explicit Instance192 variants occupy the third complete variant range, with separate hash discriminator and enlarged input-mask caches; default false parameters preserve old call sites. Clustered indexing follows all ordinary depth and color-flag variants. Mobile uses separate fp16/uber offsets in shader lookup and intentionally omits the immutable runtime fp16 choice from its input-mask-cache index. Source bounds are consistent.
- C and N are loaded directly from the 12-vec4 record before vertex user code; the Native multimesh composition branch is excluded. Local Host is not multiplied again. COLOR starts from the mesh value and is multiplied by record color; INSTANCE_CUSTOM comes from the record. CUSTOM0..3 remain locations 6–9 mesh attributes. N is used consistently for normal/tangent/binormal in the existing transform path.
- The readonly inverse builtin maps to the validated record inverse before user vertex/fragment code. Fragment model and normal use the current record selected by the flat per-instance index, not the scene Host. Alpha hash uses the record inverse. Root's separate interface review is at `../b4-spatial-inverse-model-review-20261104/REVIEW.md`; its tests remain distinct from these template checks.
- Instance192's flat payload uses reserved internal varying location10, keeping user varyings starting at15 free. Clustered keeps its scene index in the same flat vector's x component. Mobile's free internal location10 does not overlap motion12/13. No per-parity bucket/reordering was added by this component.
- Current history-valid bit chooses the aligned previous record; invalid history makes the read helper use current records and the final motion output explicitly assigns a zero vector. This cannot establish exact camera token/host/material lineage; those remain the future immutable packet caller's obligation. The native camera transform path remains in use for valid history.
- Double precision and Indexed144+Instance192 alias have explicit preprocessor refusals; actual trails selection and unsupported shader modes are rejected at the per-material C++ boundary (incidental global-group trail variants intentionally compile). Actual skin/morph/dynamic mesh and material-bound/history recipes are resource/caller admission checks, beyond ShaderData's documented structural predicate. No actual External caller exists in this slice, so those missing integration steps are not mislabeled as regressions in an implemented draw path.
- Native inverse work is usage-conditional. Spatial builtin is readonly in vertex/fragment only; GLES uses its existing composed model matrix. No Compatibility external output support is inferred.

## Independent verification

`extra_template_checks.py` compiles the actual expanded renderer templates with independent manually translated vertex/fragment snippets, reusing only the author's include resolver. It exercises color/custom plus inverse/normal reads, TBN, normal/bent-normal mapping, vertex lighting, alpha-hash+motion+multiview, material side-checks, shadow and dual-paraboloid, both specialized/uber, and Mobile fp16/fp32. Initial and final-helper reruns each produced **72 stages + 36 links passed**, every stage also passed spirv-val. The final helper includes both I192-R1 and uber cull fixes; `EXTRA_RESULTS_INITIAL.json` retains the earlier manifest. `EXTRA_RESULTS.json` and `extra-template.log` record commands/results/source and include hashes. These checks do not invoke Engine ShaderCompiler, ShaderRD group lifecycle, a rendering device, or numeric image observation.

## Required integration/qualification still open

Before native draw enablement, retain guarded current/previous bindings and exact generation/read lease, validate firstInstance=0 command ranges and mesh eligibility, pass the new variant/input-mask bool, prevent distinct packet merging, bind the exact per-view packet, and keep material/pass cull semantics through specialized/uber selection. Hardware cull must stay disabled, with material FRONT_FACING and side-check using the same mirror-adjusted logical face. Backend/pass mirror truth-table calibration against ordinary ArrayMesh remains mandatory; template compilation cannot sign it. The final helper consumes existing `uc_cull_mode()` push constants for uber variants and spec4 for specialized variants. This matches the real renderer caller, whose uber pipeline key sets hardware cull disabled while retaining original material/pass cull in uc bits. The prior specialized-only spec4 assumption no longer imposes that incompatible uber caller requirement. Both paths still share logical face correction. `REVIEWED_FILES.json` locks the final eleven production file hashes and formal contract hashes.

The support-predicate branches (POSITION, skip/world coords, modelview/projection, point size, native trails) and hash/variant/cache lookup need real engine tests as well as syntax/template checks; the current author fixtures manually set defines and do not execute those C++ predicates. Root's language-builtin doctests are also not a substitute. No claim of full B4, material qualification, camera lineage, transparent velocity blending or GPU acceptance is made.
