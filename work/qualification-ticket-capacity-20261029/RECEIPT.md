Status: **limit reproduced; safe reuse not implemented**. Worktree HEAD at probe creation was `93159e4c924aa4645b0f3f2371e45000a02bafa5`, but the editor reports build hash `68cc71778`; the runtime result belongs to the measured binary, not a proven rebuild of that HEAD. The editor binary, probe DSO, probe sources, runtime inputs and SDK archive measured during the run are recorded in `METAL_RECEIPT.json`; `BUILD_RECEIPT.json` records the source and SDK archive around the build. Compiler headers and the toolchain were not completely hashed. The editor and SDK archive may later be rebuilt. The DSO is retained locally and excluded from Git.

The actual non-headless Apple M3 Pro Metal/mobile main RenderingDevice used one original guarded library session and bridge. On that bridge the probe created a real E05 storage backing and issued 128 distinct upload-preparation requests, each with a new fixture record generation and original backing reference. Each accepted ticket was cancelled before upload or recording, observed in its cancelled terminal state with no facts, and acknowledged. Request 129 was refused with Godot Error 5, reason 19, and no ticket. Replaying the first request with a fresh QRT transport operation was refused with Error 33, reason 17, and no ticket. The original storage was then physically returned and acknowledged, and the bridge, session and guarded extension closed successfully. `metal.log`, the machine-checked `METAL_RECEIPT.json`, and the source and runner preserve the observation.

This test uses fixture-issued request fields; it does not establish a production B/E06 issuer, actual upload, dispatch, completion, readback, a capacity fix, or end-to-end ANGE acceptance. It does not prove all request histories exhaust identically or authorize reuse by discarding V1 tombstones. The separate storage test previously demonstrated 128 actual storage frees and a 129th refusal; the two results cover different owner tables. Correct reuse still needs an authenticated source sequencing and retirement contract, live-reference and replay rules, and tests spanning those boundaries.

Independent read-only review (`/root/t1_independent_review`) traced the original probe and runner, confirmed the log's 128 distinct tickets and both refusal outcomes, and agreed with the no-effect scope. A separate source review found the active `ProgramPreparationStore` issues strictly increasing per-store request serials for new probes; equal per-slot generation alone is therefore not evidence of a reachable collision within that store. Global uniqueness across different Store instances or rebuilds sharing a bridge has not been established.
