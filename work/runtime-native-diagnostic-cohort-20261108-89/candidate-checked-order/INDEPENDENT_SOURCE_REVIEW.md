## Algorithm checks

1. **Closed single-dispatch resolver** (`after/.../rendering_device_graph.cpp:165–180`). It accepts only compute instruction kind2 or closed compute-list kind4; original `_resolve_record_command_index` calls `contains_record`, which validates graph instance/frame, kind, offset, registered instruction location and recorded command type. An open instruction can exist but cannot resolve to a recorded closed list. `compute_record_offsets` is populated only by actual direct/indirect dispatch additions; counting matching list indices therefore correctly refuses zero/multiple dispatches without parsing unrelated bind instructions. Both producer and reader use this resolver. A direct/indirect dispatch is an accepted mechanical graph record, not proof that any shader initialized bytes.

2. **Pending later source use** (183–203). Original `add_compute_list_usage` updates `compute_list_index`/`compute_list_usage` before closure, but `_add_command_to_graph` changes `write_command_or_list_index` only at actual list end. Merely comparing the old writer would therefore incorrectly accept a pending overwrite. The new scan requires the tracker's latest compute-list index to occur in a recorded closed compute-list command. This rejects a later open source read or write while retaining legitimate closed readonly readers. An unrelated open list is not detectable from this tracker: original RD no-active-list ownership remains the explicit caller requirement, correctly stated in the header/README.

3. **Overwrite despite transitive path** (191; 206–241). On transitions=false canonical whole-buffer trackers, `_add_command_to_graph` assigns the actual command index to `write_command_or_list_index` for writes, and retains it for reads. A later overwrite makes A→B→reader transitively reachable, but equality to selected A fails. The test's literal path length2 uses original BFS machinery and independently proves why reachability cannot replace freshness. A disjoint later buffer update is also a whole-buffer writer; refusing it matches the declared conservative granularity.

4. **Actual reader/direct hazard** (206–241). Latest writer equality is followed by exact STORAGE_BUFFER_READ current/compute usage, producer<reader, current tracker command_index==reader, membership in this tracker's real read_full_command_list, and a direct stored producer adjacency. Original whole-buffer readonly hazard registration inserts precisely these facts. Explicit sync to an unrelated reader can supply adjacency, but cannot supply this tracker's reader membership/current command identity; the unrelated-reader negative is valid. The new traversal bounds node indexes and visits without allocating. It does not fabricate an edge or accept a transitive-only path.

5. **Transition/callback refusal** (184–188). Original different-usage handling promotes even readonly buffer state transitions to write_usage when `API_TRAIT_BUFFERS_REQUIRE_TRANSITIONS` is true. Rejecting the entire trait avoids mistaking transition bookkeeping for content mutation and is correctly conservative. `has_driver_callbacks` scans actual recorded commands; an already-recorded opaque callback refuses freshness regardless of declared resource list. This check is not a guarantee against future callbacks or external writes; same original writer ownership must span preflight/append/observation.

6. **Identity/unsupported tracker checks**. Null or driver-ID-less tracker, texture/AS/parent/write-list state, wrong tracker frame, draw/ray usage, ended graph, malformed/wrong graph/frame/kind handles are rejected by the new predicates plus existing resolver. Canonical Buffer tracker identity is an explicit original-RD caller precondition, not authenticated by this API: a copied/foreign tracker with coincident fields cannot be distinguished here. The source does not claim otherwise. A returned bool is not authority and must not be stored/replayed as a permit.
