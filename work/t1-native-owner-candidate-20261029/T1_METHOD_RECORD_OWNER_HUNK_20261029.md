# T1 method record on the original native owner — 2026-10-29

Status: **implementation candidate; not yet an adopted ABI or runtime result**. This supplements the original four-method plan and supersedes any suggestion in the earlier T1 sketches that Godot must authenticate C++ source, C05 map or B's slot as an independent capability. The source of that boundary is design main `7c84ee02effb10021d402311990fbbec931590b4`, `IMPLEMENTATION_ROUND_20261025_ROOT.md` §“Cold-link result representation and native T1 boundary decisions”. ANGE's original C04/C05/E06 owners validate their retained source, selected map/slot/version and actual resource views; D validates the real original bridge/session/ticket, native units, resource children, their native associations and lifetimes. Digests and caller-supplied IDs correlate a request but do not create authority.

## Existing incompatible V1 behavior

At Godot `238e386f60374bc1b936b37290285bc12543a7d7`, `qualification_record_preflight` and RT kinds 6/9 require nonzero `sample_count`, `range_end-range_begin == sample_count` and `body_groups_x == ceil(sample_count/64)`; the preflight additionally requires word 1 of both push blocks equal to `sample_count`. The preflight accepts exactly one shader set at index 0 per phase and only buffer/shader reverse dependencies. `qualification_record_append` binds that one set, records one capture and one body and reads one buffer interval. RT and prepare validate the upload role in V1's eight-value numeric namespace. These checks are part of V1 and must remain intact.

Method roles are a different ten-value `MethodQualificationRole` enum in `ANGE/src/particle/gpu/gpu_qualification_source.h`; matching integer 6 means Method RawParameters in one namespace and numeric RawInput in the other. Increasing a limit or casting one enum to the other is incorrect. C04/C05's actual sparse descriptor map may contain multiple sets and texture/sampler members; it cannot be reconstructed from an ordinal or a digest. The current D record preflight also permits an unmarked pipeline when `cell` is null; the method arm must instead validate the actual named original E06 native-unit child and its shader/pipeline association.

For original store domain 0, the original body source (`gpu_method_qualification_construction.inc`) checks the actual first/end range before invoking the method. It still needs a real one-group body dispatch, capture/body graph facts and the original E24 P writable target readback of four words plus two guard words (at least 24 bytes). `count=1` is not a substitute for zero domain; no Q RawResults role is manufactured. The remaining outputs/fault/control facts follow the actual original vector and owner contract, not a guessed packing.

## Recommended cohesive original-owner hunk

1. **Versioned same-ticket prepare.** Retain the existing bridge, its one RT cell and the same ticket. Each typed operation independently reserves, activates, observes and acknowledges that cell; the whole transaction is not one admission. Before the ticket exists, prepare holds the original bridge/RT cell/CodeHold and copied input, atomically creates and retains the prepared ticket before any native resource effect, and recovers a lost prepare reply through the same key/occupied cell without creating another ticket. Each subsequent operation pins that exact ticket at its own admission. The new arm copies and validates the original request/attempt/session association, real existing E05 buffer child/range/serial, original E06 native-unit children and a bounded native resource plan. Before any texture, sampler, set or upload effect it reserves the actual child/RID/return slots, source bytes, per-set dependencies, graph/segment/native/readback observations and physical-use obligations. Failure before an effect is an original refusal; after a known or possible effect the original child and ticket keep the prefix. The method upload plan uses its own closed versioned native owner/range representation; D validates the real E05 child and byte range, while ANGE owns semantic role-to-source selection. No V1 role number is reinterpreted. Duplicate calls compare the full original request and retain once.
2. **Original native resource and set ownership.** The fixed texture request is real RGBA32F 2×2×1, one layer/mip/sample, exact supported sampled/update usage, 64 raw source bytes; the sampler is nearest/clamp with the original remaining explicit state. TextureDimensions carries the original metadata path and no sampled descriptor. Each set is created against its actual original native unit's shader and checked reflection, with a complete bounded ordered list of set/binding/array/type and real retained buffer/texture/sampler child views. D checks actual native association, format, usage, access, byte/subresource extent and reverse dependencies, not C05 semantic ownership. A sampled texture descriptor uses the real sampler then texture order. Reflection checks descriptor type, count and interface; D checks the actual native view's subresource, format and usage, and the original ANGE C05 owner verifies the expected view and content version. Existing set owner and dependency/physical-return chain are extended in place; no second registry, public RID enrolment, fallback format or synthetic completion.
3. **Versioned method record and exact result.** In the same ticket keep separate original dispatch range, actual source domain/control and selected readback source/range(s). The packet carries the real two native-unit children, full per-phase set-index→set-child arrays, actual 16-byte phase push blocks and checked dispatch envelope. For the selected fixed method, zero logical work records one real body group whose original guarded entry returns before the method; positive work uses the original checked bounded dispatch. Validate the original push layout and bounds, not `sample_count=1`. Select the real P target for store, real Q result for the other recipes, and all required original guard/fault/control ranges. Pin those exact owners and bind each real set; append actual capture→body→readback graph records in the existing ticket. Report each original range and exact bytes; one buffer/range is sufficient only if the original source owner proves it covers every required output. A bounded same-ticket multi-range readback is otherwise required. No fake success, body, result or method invocation follows from count zero.
4. **Checked texture and retirement.** Reserve segment count from actual driver alignment and the 2D row partition, not `ceil(bytes/32)` alone. Each real append records source row stride/interval, destination region, staging offset/stride/size and original graph handle; Validate checked arithmetic and complete nonoverlapping logical source/destination coverage before the first effect. Actual staging offsets and strides become known at each allocation and must be checked before that segment's append; retain the real accumulated prefix if a later allocation or append fails. Use a checked nonwaiting continuation in the original RD/graph path; ordinary `texture_update` may append before a later staging action and can enter `FLUSH_AND_STALL_ALL` or `STALL_PREVIOUS`. Each actual prior known/possible prefix remains owned across such pressure; do not invoke that blocking legacy path on maintenance. Same-ticket graph→native issue/completion and physical staging return discharge each exact segment. The original cancellation admission closes new work while already admitted work publishes its retained prefix once. A successfully published RT reply with a possible effect carries outer OK, the original child and typed inner error. A lost or failed reply does not prove a delivered child: retain the same original owner prefix; define recovery against the same occupied RT cell and identical original operation key without replaying effects, including the case where the caller lost the ref. Non-ticket-child observation/release and publication failure rules must be explicitly versioned. Reverse dependencies keep set→texture/sampler/shader order until actual physical return. Vulkan sets use a non-linear pool and a checked original driver result; an ignored `vkFreeDescriptorSets` error cannot become a successful return.

**Capacity is cumulative.** Current bridge arrays retain acknowledged ticket/storage/native-unit slots until bridge close, and exact old request replay refuses an acknowledged operation by finding its retained identity. Merely deleting a cell when currently unused would remove that replay tombstone and can admit the same old create again; unique output serials alone do not prevent duplicate effects. The 23 occurrences and max32 attempts require a proof for the actual resource counts, retained tombstones, retries and other live owners or a reviewed extension of the original bounds. No claim is made that 128 slots suffice. A reclaim design must also discharge ticket↔physical reverse pointers and preserve old-operation refusal without a second registry.

## Three interface decisions needed for the executable hunk

1. **Method request and readback layout:** B/C05 must supply the original domain/range, actual 16-byte phase push values, set indices and complete real bindings for each method, plus selected readback ranges including fault/control and P target/guard for store, all from the same retained request. Recommended: a bounded ordered list of real owner-backed ranges in the existing ticket; use one range only when the original owner proves the complete required data are contiguous. Define total result capacity and exact per-range fact/copy association.
2. **RT wire:** A/D must select exact versioned request/observation tags, payload and result/segment layouts, sizes and SDK source tuple. Recommended: extend the existing one-slot RT transport and existing original ticket, not a second delivery channel; retain V1 byte-for-byte. Existing `GDExtensionQualificationUploadSegmentV1` cannot describe 2D rows/staging and must not be reinterpreted. The current 312/200/4096 maxima are not proof that complete set arrays, multi-range output and texture segments fit.
3. **Budget and safe reuse:** A/B/D must give the existing profile's actual maximum simultaneously/cumulatively owned buffer, unit, set, texture, sampler, ticket, graph/native and segment counts for all 23 occurrences and 32 attempts. Recommended: keep stale-operation identity under the original owner until a proved safe reclaim, otherwise charge cumulative tombstones and reject before effects at the real limit. Raising 128 without an exact bound, or opening a new session per occurrence, is not a capacity proof.

Before implementation/adoption, review the actual record/control values from B's landed owner, exact append/return interfaces and all partial-effect, close/cancel, same/foreign owner, cross-frame and zero-domain branches. This proposal does not issue a B slot, publish a source, grant a ticket, build or run a GPU test.
