# T1 method-resource layout experiment — 2026-10-29

Status: **draft experiment; not an ABI, implementation, adoption, or GPU acceptance**. Source basis: Godot `939ed617ce8a0a04b5fed51563dc369649c9f76c`; the accompanying `T1_D_OWNER_CANDIDATE_20261029.md` defines the still-open owner and lifecycle constraints. This experiment gives reviewers concrete sizes to challenge; it does not supply the missing B issuer or authorize a native effect. Names and values may change when the responsible owners adopt an actual interface.

## Layout and scope

The sibling `t1_layout_candidate.h` is a standalone C11 illustration, not included by production code. `T1Abi` and `T1Ref` have the same field shapes as the existing `GDExtensionDeviceExitAbi` and `GDExtensionQualificationTicketRefV1` in `core/extension/gdextension_interface.gen.h`; matching bytes do not make all refs interchangeable. In a real ABI, use distinct typed child/ticket/unit handles and existing header definitions. The `abi.struct_size` and version rules must be defined per actual entry point; this experiment does not decide whether nested origin uses its own size or the enclosing request's size. Reserved fields and padding must be initialized and validated; serialization must not compare or expose uninitialized padding. Enums, flag masks, valid zero values, endianness and all error/status values remain to be specified. Cross-language declarations require independent C and C++ checks on every supported ABI, not merely these local assertions.

On Apple arm64 and x86_64 targets with Apple clang 21.0.0, the sibling checker asserts alignment 8 and the following byte sizes: origin 184, texture request 256, sampler request 240, set request 256, create report 88, retirement report 128, segment 120. Origin's request digest begins at 96 and allocation generation at 176. Run:

```sh
clang -arch arm64 -std=c11 -Wall -Wextra -Werror -fsyntax-only work/t1-native-owner-candidate-20261029/t1_layout_candidate_check.c
clang -arch x86_64 -std=c11 -Wall -Wextra -Werror -fsyntax-only work/t1-native-owner-candidate-20261029/t1_layout_candidate_check.c
```

These sizes alone do **not** make the experiment compatible with RT V1. Current RT hard-codes kinds 1–9 and exact per-kind request/result sizes; adding a kind requires explicit versioned validation, dispatch, observation and release support. Its 312-byte request/200-byte result maxima happen to exceed each illustrative standalone record, but the actual wire must also account for any header, refs, complete set members and upload segments, their count and alignment. Current segment storage is `GDExtensionQualificationUploadSegmentV1`, not the illustrative 120-byte texture segment. Define and budget a versioned segment/result transport before implementation; no truncation or reinterpretation of the old type. Check all multiplication, addition and allocation bounds and reserve them before effects.

## Authentication and transactional scope

The scalar IDs and digests in `T1Origin` are correlation data only, not capabilities or proof of source, allocation, association, or completion. Before a create/upload, the original bridge must authenticate the same prepared ticket, attempt, library/session and the actual B-owned source/slot reservation with the original checked map and source version. The current consumer checkout does not expose the proposed B binding transaction described in the companion candidate; its actual issuer, signature, lifetime, and correlation with C05 are unresolved. A caller-supplied digest, RID, serial, or map is not a substitute. No new authorization is implied by this document. The illustrated origin is also structurally incomplete: it does not identify the original record slot, typed BindingEpoch/phase scope, selected physical unit, C05 occurrence/source version and full view association. A shader set index is not a capture/body phase or source proof. B/A must specify the original typed issuer and its exact association; test equal-valued neighboring slots and sources in the same session, wrong phase, slot, version and selected unit before accepting any effect.

The existing V1 prepare checks real existing buffer RIDs before creating the prepared ticket. A versioned prepare must first validate those real E05 buffers and reserve all texture-specific child, RID, dependency, return, segment and source/slot capacity on the same ticket before a texture effect. It must atomically establish the texture writer/pin claim and mark the ticket non-retired before that effect. Define rollback of reservations only when absence of an effect is established. A failed or unknown prefix retains its original child, claims and observations; accepted work after close is allowed to return through its original admission, while new work stays closed. The request layout shown does not itself implement this ordering. Before adoption, specify the exact create/close/cancel linearization and lock/lifetime rules separately for RT accepted and queued but not executing, executing when cancel closes admission, and effect completed but child result not yet published. For each, determine whether the one original admitted call may start or finish, how its prefix is retained and how cancellation waits or observes it; no subsequent work is authorized. Prove the lock order and owner lifetime against the existing child claim under Registry lock and driver call outside it, retire's RD try-lock followed by Registry lock, and record's Registry lock followed by RD try-lock; no blocking inversion or freed child may be introduced. These precise rules are not yet designed here.

`T1SetCreate` deliberately has no complete member payload: `map_digest` and `member_count` alone are insufficient. The actual bounded payload must preserve the complete ordered sparse set, each set/binding/type and descriptor count/array element, real original child, access, and complete view: buffer offset/length/stride or texture format and complete mip/layer/aspect subresource, together with shader and source version and all dependencies, with original-map authentication. Define exact member layout, maximum, deduplication and conflict/alias rules; validate against actual shader reflection. The sampler-with-texture order is sampler then texture. No guessed RID or digest-derived owner is accepted. A dimensions-only method has no sampled descriptor.

## Upload, reports, and retirement

A 2×2 RGBA32F texture has 64 source bytes, but those bytes are not a buffer descriptor. Keep original raw bits and source ownership. The actual checked, nonwaiting upload must bind every real graph append to its original ticket and retain source interval, region, staging allocation, native issue/completion and staging return; the illustrative `T1TextureSegment` leaves the staging and native fact mapping unspecified and is not sufficient for acceptance. One source interval cannot unambiguously describe a column slice across multiple rows: specify original source row stride, covered interval and bytes for every row, staging offset/stride/size and alignment, checked arithmetic, and complete non-overlapping coverage of the intended region. Bind those exact row mappings and staging allocations to the graph handle and native/staging observations on the same ticket. Bound the actual segment count from driver alignment/partitioning; no claim that one segment or the current 4096 ceiling is automatically sufficient. The existing ticket also has a shared 4096-fact capacity, and its resource pin and physical-use vectors reserve 128 entries: calculate the combined per-ticket graph, native, readback and texture obligations against the real capacity and allocation rules, including prior facts and accepted prefixes. A segment count alone is not that proof; unknown backend fan-out must not be guessed. Partial append, no-append proven absence, unknown effect, cancellation and late completion require separately observable outcomes.

For create, the outer RT result may be non-OK with zero output only when no child or effect was retained. Once a child or possible effect exists, preserve it with outer OK and a typed native error plus known/possible masks. The illustrative create report has no revision, and its retirement report has no known/enqueued/freed/absent/unresolved masks, despite the companion candidate requiring those observations. Neither layout is adequate yet: add a stable observation revision and the necessary masks, or prove a fully specified single-child state model distinguishes each known prefix, unknown, return and idempotent retry without losing information. Define exact state transitions, mask meanings and operation idempotency before adoption. RT V1's state-3 release checks a ticket and cannot simply release a non-ticket child; its replacement must specify retries, child retention, close and physical-return evidence. Candidate `rid`, serial and event fields are observations, not authority.

Retire set before referenced texture/sampler/shader using actual reverse uses and cross-frame dependencies; release those dependencies only after the set's physical driver return. Nonlinear descriptor allocation and a typed backend return are necessary to distinguish a successful Vulkan descriptor free from an ignored `VkResult`; unknown/device loss stays unresolved. Sampler/texture backend call semantics also need supported-backend validation. Never infer physical return from RID erasure or enqueue. A later close/cancel cannot publish readiness; it retains prefixes and stops new upload/record work. Current 128-element arrays are cumulative until safe reclaim, so account for the original 23 occurrences (4/3/14/2), up to 32 admitted attempts, retries, retained tombstones and unknowns; reject before effects when a complete reservation cannot be proven. No capacity sufficiency is claimed.

## Review and acceptance still required

1. Original B/C05 owner publishes and adopts the pre-effect source/slot transaction and complete map; A adopts exact SDK and transport declarations.
2. Define checked texture append through native completion and physical staging return, exact versioned layouts/tags/statuses and the ticket/non-ticket RT release contract. Establish supported backend and descriptor free evidence.
3. Review and test no-effect and each partial-effect failure, duplicate and foreign requests, capacity exhaustion, close/cancel races, source/view replacement, cross-frame reverse dependencies and unknown returns. Real non-headless main-RD four-method acceptance is separate from C layout checks.

No production code was changed and no engine build, runtime or GPU validation was performed for this layout experiment.

## Independent review

Read-only reviewer `/root/t1_independent_review` inspected the layout experiment, companion candidate and relevant Godot source. The review identified missing per-row texture source/staging mappings, complete set member fields, create report revision and retirement state/masks, original record/phase/unit/source association, and explicit create/close/cancel lock and lifetime rules. The proposal was revised to identify each as an unresolved adoption requirement; the reviewer confirmed those revisions and concluded that this remains a draft, not an adopted production ABI. The reviewer did not modify files or independently run the C checks, a build or GPU tests. The two architecture checks above were run by the author on Apple clang 21.0.0; they verify only the asserted C layout.
