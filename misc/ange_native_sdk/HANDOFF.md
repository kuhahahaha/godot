# Matching custom native interface SDK

The three integration products are `include/gdextension_interface.h`, `include/godot_cpp/core/gdextension_interface_loader.hpp`, and `src/gdextension_interface_loader.cpp`. All three were regenerated through the unchanged original generators from reviewed Core commit `541649866ce31e816d822a6dbbdd7ae60c6d1a7d`, schema SHA-256 `4bb5c2f99c5c574ddb0fa1a6c1c069e41f89bc17a65da08d212b799858ba438d`. This successor adds the original Storage domain/finality surface; no class API, archive, engine or extension binary is included.

`PROVENANCE.json` retains the historical schema origin and unchanged formal generator/support origins. `INPUT_PINS.json` pins the successor schema, probes and three actual products. Its authenticated generator receipt remains the historical authentication of the unchanged tools; successor expected product hashes were obtained by invoking those tools on the reviewed new schema, then independently repeated by original replay. It is not an old product verification republished as new evidence.

Run `python3 -B /absolute/path/to/sdk/replay_sdk.py` to check inputs, regenerate all three products, byte-compare against the successor pins, repeat generation in a temporary directory, and run C11/C++17 ABI and generated-loader syntax probes. In-place replay rewrites verification and requires manifest refresh. `verify_sdk.py` checks manifest and preserved historical cohort, then performs fresh replay in a temporary copy without changing delivery.

The probes assert ABI header16, Domain24, Finalize40 and every member offset, the original 24-byte procedure result (native_error/reason/expected/actual), exact function-pointer signatures, C++ standard-layout/trivial-copy properties, original QRT request56 and offsets, kind25, and its uint64 acknowledgment8. The kind25 carrier requires request_bytes40, result_capacity8, payload_bytes0 and segment_capacity0; result is acknowledged generation only on OK and zero on Busy/refusal. Existing Core Task1 tests own execution semantics; SDK syntax cannot prove them.

Load `device_session_qualification_storage_domain_install_v1` and `device_session_qualification_storage_generation_finalize_v1` through each original guarded InitData lookup. Retain these typed capabilities with that original InitData/bridge lifetime; never assign the ordinary generated `device_session_` globals. The legacy generated loader deliberately does not request these names and leaves their globals null. Unopted clients retain existing behavior. Configured production must require both capabilities and matching Core/compiler cohort before installing its exclusive domain, and must refuse configuration if either is absent; it cannot silently fall back. Successful Native domain installation is also required before enabling production. This package does not change B's consumer installation implementation.

Its actual headless guarded/legacy run verified43 raw lookups, original registration/lifecycle/unload, generated ordinary-loader success with no device_session lookup and null new globals, and missing-either capability refusal. It used the pre-publication Task1 executable, not a final controlled successor cohort. No GPU, archive, production domain call, class API, A/B build or World acceptance is claimed.
